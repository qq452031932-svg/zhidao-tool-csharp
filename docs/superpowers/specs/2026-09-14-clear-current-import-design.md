# 清空当前导入设计

## 目标

当用户误选 Excel 或误粘贴链接后，可以在开始转存前一键清空当前导入数据，回到尚未导入的空白状态。该操作只删除本机数据库中的当前导入草稿及其暂存行，不调用百度网盘接口，不删除网盘文件、远端分享链接或已结束任务历史。

## 方案比较

1. **只清空界面**：实现最小，但错误导入仍留在数据库，重启、恢复或后续维护时仍可能出现，不满足用户目的。
2. **事务删除尚未使用的当前导入（采用）**：数据库内复检当前会话尚未创建、追加或关联任何批次，再删除其暂存行和会话；界面随后原子恢复空白。边界清楚且不会误伤实际任务。
3. **允许清除任意导入及关联任务**：能覆盖任务开始后的情况，但会与运行中/已结束任务、结果和恢复证据形成大范围级联，风险高且与本次需求无关。

## 用户界面

- 在批量转存顶部的“选择 Excel”附近增加“清空当前导入”按钮，使它与用户的误导入动作处于同一操作区域。命令由拥有顶部工具栏和配置状态的 `TransferWorkspaceViewModel` 统一协调。
- 仅当存在捕获的当前导入会话、导入/工作台均不忙且当前配置可编辑时启用。
- 点击后显示确认框，明确展示当前导入条数，并写明：只删除本地待处理导入，不影响百度网盘文件和分享链接。
- 默认按钮为“否”。取消时不改变任何状态。
- 成功后仅在被清除的会话仍是当前会话时执行完整复位：使导入分页和编辑代际失效，清空表格、选择项、分页游标、行数、统计文字、恢复状态和当前会话，丢弃 Excel 恢复源；同时解除向导保存的导入上下文，清空工作台待处理行账本，并刷新开始/配置命令。最后显示“已清空当前导入，可重新选择 Excel”。

## 应用与数据库边界

- 新增专用的当前导入清理契约，输入只包含待删除的导入会话标识。
- SQLite 实现在单个事务内重新读取会话，并对全部已知批次关系做穷尽检查，确认以下位置均无引用：
  - `CreatedBatchJobId` 为空；
  - `AppendToBatchJobId` 为空；
  - `BatchJobs.ImportSessionId`；
  - `BatchCreationReceipts.ImportSessionId`；
  - `ResourceItems.StagedImportRowId` 经 `StagedImportRows` 指向当前会话。
- 上述任一关系存在时，即使两个会话标记列为空，也返回批次冲突且不删除任何内容。
- 删除前还要检查其他导入会话的 `StagedImportRows.DuplicateOfStagedRowId` 是否反向引用当前会话的行；存在时返回明确的本地依赖冲突并保持两个会话不变。
- 满足条件时先删除该会话的 `StagedImportRows`，再删除 `ImportSessions`；`ImportColumnDefinitions` 与 `StagedImportRowPayloads` 只通过现有外键级联删除。删除数量、最终残留或外键检查不符合预期时回滚。
- 会话不存在时返回“已经清空”，保证重复点击/重试幂等。
- 一旦已经生成或关联批次，返回冲突并保持全部数据不变。此时用户应等待任务结束，再使用已有的“清空转存历史”。
- 清理由工作台捕获当前会话标识后发起，并与导入、编辑、分页加载及工作台任务创建共用互斥/忙碌边界；迟到的异步页面结果必须通过会话/代际检查丢弃，不能把已清空的数据重新显示出来。数据库成功后若用户已切换到新会话，不得清空新会话的界面或向导状态。
- Excel 恢复源只在数据库事务成功后丢弃，失败或取消时保留。

## 测试

- Application：未关联批次可删除；两个标记列、`BatchJobs`、`BatchCreationReceipts`、`ResourceItems` 各自独立存在引用时均冲突；不存在时幂等；异常时事务回滚。
- Infrastructure：真实 SQLite 验证暂存行、列定义、行载荷与会话完整删除；所有批次关系保护；跨会话重复行反向引用返回本地依赖冲突；外键完整性和重复调用。
- App/ViewModel：按钮启用状态、确认/取消、成功后导入与向导完整复位、冲突保留数据、清理期间互斥、会话切换保护、迟到分页结果无效化，以及旧向导配置无法启动批次。
- XAML：按钮文案、命令绑定、无障碍名称与危险操作样式。
- 回归：导入、开始转存、历史清理和 OTA 更新相关聚焦测试与 Debug 构建。

## 非目标

- 不删除正在运行或已结束的批次。
- 不改变已有“清空转存历史”的语义。
- 不清理百度网盘文件、分享链接、账号或其他模块数据。
- 本轮不发布服务器版本；生产 OTA 发布另行执行并在发布前再次确认版本号和产物。
