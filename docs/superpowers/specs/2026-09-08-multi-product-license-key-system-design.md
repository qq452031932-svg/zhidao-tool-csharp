# 多软件卡密授权系统设计

## 目标

为 SuperPan 及后续 Windows 桌面软件提供一套自建、轻量、统一的卡密授权系统。管理员在现有 `ota.fanfh.cn` 管理后台中维护软件、套餐、卡密和机器绑定；客户端以同一张卡在同一台电脑上使用套餐允许的多款软件。

本期优先保证简单、易用、低服务器负载和与现有 OTA/其他网站隔离，不建设支付、代理商或客户账户体系。

## 已确认规则

- 卡种固定为月卡 30 天、季卡 90 天、半年卡 180 天、年卡 365 天。
- 卡密首次成功激活时开始计时，所有到期判断使用服务器时间。
- 管理员可以创建多款软件；软件拥有永久不变的内部 ID，改名不影响授权。
- 软件只能停用，不能删除。停用某软件只拒绝该软件的新验证，不影响套餐内其他软件。
- 管理员创建套餐时可以选择一款、多款或全部软件。
- 卡密绑定套餐而不是绑定单一软件。套餐成员动态生效：新增软件后，已有卡密在下一次在线验证时获得授权；移除软件后，已有卡密在下一次在线验证时失去授权。客户端无法连接服务器时，旧授权最多持续到既有 30 分钟租约到期，服务端不承诺主动撤回已经签发到客户端的离线租约。
- 一张卡密绑定一台电脑。同一台电脑只需激活一次，同一张卡授权的其他软件自动识别。
- 更换电脑或重装导致机器指纹变化时，只能由管理员手动解绑；用户不能自行解绑。
- 管理员续费直接延长原卡密到期时间，不换卡。延长基准为服务器时间与当前到期时间的较晚者。
- 删除卡密是永久删除：活动数据库中同时删除卡密、机器绑定和服务端租约记录，不提供回收站或恢复按钮。已签发到客户端的离线租约无法主动收回，但最多 30 分钟后失效。
- 软件启动和执行远端核心操作前验证，不进行固定周期轮询。
- 服务器临时不可连接时，最近一次成功验证结果最多宽限 30 分钟；首次激活没有离线宽限。
- 已开始的批次不因卡密随后到期、删除或断网而强行中止；用户手动继续、手动重试、进程重启后恢复或开始新任务前必须重新验证。同一运行中批次内部的自动重试不重新验证。
- 不显示到期前提醒。

## 总体架构

### 统一后台与内部隔离

管理员继续访问 `https://ota.fanfh.cn/admin/`，使用现有管理员登录。后台新增：

1. 软件管理
2. 套餐管理
3. 卡密管理
4. 设备绑定

卡密运行时使用独立的 `superpan-license` 服务、独立 loopback 端口和独立 SQLite 数据库。Nginx 只把公开验证接口代理到该服务；服务不访问 OTA 发布目录和其他网站目录。

管理浏览器仍只与现有 OTA 管理服务通信。OTA 管理服务使用仅限 loopback 的内部凭据调用卡密服务的管理接口，因此管理员只登录一次，卡密服务的管理接口不直接暴露公网。

公开客户端接口使用同源路径：

- `POST /license-api/v1/activate`
- `POST /license-api/v1/validate`

服务端健康检查仅允许本机或受控验证脚本访问。OTA 静态下载不依赖卡密服务；卡密服务停止时，OTA 稳定通道仍可正常下载。

### 客户端集成

每款软件构建时嵌入自己的不可变软件 ID 和卡密服务公开验证配置。客户端共用一个本机授权存储，卡密用 Windows DPAPI `CurrentUser` 范围加密，不以明文写入配置、数据库或日志。同一 Windows 用户下的多款软件自动共用；同一物理电脑上的另一个 Windows 用户首次使用时需重新输入卡密，但稳定机器指纹相同，服务端视为同机，不要求管理员解绑。

共享存储可以保存多张卡。每款软件启动时选择一张当前允许该软件的卡进行验证；同一张卡在第一款软件成功激活后，其他被套餐授权的软件无需再次输入。

客户端只提交卡密、软件 ID、机器指纹哈希、业务请求 ID、时间戳、请求随机数和必要的协议版本。机器指纹优先由标准化后的 Windows `MachineGuid` 与 BIOS UUID 组合后哈希；其中一个不可用时仅使用另一个，二者都不可用时拒绝激活并提示无法取得设备标识，不得生成随机指纹。原始硬件字段不上传。

## 数据模型

### 软件

- 不可变软件 ID
- 显示名称
- 启用/停用状态
- 创建时间、更新时间

### 套餐

- 不可变套餐 ID
- 套餐名称
- 当前包含的软件 ID 集合
- 创建时间、更新时间

套餐成员是动态关系，变更后在客户端下一次在线验证时对所有引用该套餐的现有卡密生效。客户端暂时离线时，变更前已签发的租约最多继续有效 30 分钟。

### 卡密

- 不可变卡密 ID
- 所属套餐 ID
- 基础授权天数：30/90/180/365
- 未激活总授权天数（用于累计生成后的后台续费）
- 未激活/有效/已到期状态（删除后记录不存在）
- 首次激活时间、到期时间
- 后台备注
- 生成批次与创建时间
- 绑定机器指纹哈希
- 卡密前 8 位和末 4 位（仅用于后台索引筛选）

完整卡密在服务器中使用独立密钥加密存储，用于后台复制与导出；密钥文件由 root 所有，仅授权服务所属组可读，权限为 `0640`，服务本身使用非 root 用户运行。卡密验证和完整卡密精确搜索使用独立的带密钥摘要索引，不通过解密后全表扫描。前缀筛选固定匹配前 8 位，末尾筛选固定匹配末 4 位，分别使用独立普通索引；不支持任意长度的模糊卡密搜索。列表默认遮挡卡密，仅在管理员明确复制或导出时解密。备注支持包含搜索。后台备注不下发客户端。

### 验证租约

客户端保存服务器签发的短期验证结果，包含卡密 ID、机器哈希、软件 ID、签发时间和最迟宽限时间。租约最长 30 分钟，仅用于服务器暂时不可连接时的宽限，不能延长卡密本身到期时间。

### 批次授权边界

“运行中批次”是指当前进程内，在一次成功在线验证或仍有效的离线租约之后，由用户明确启动且尚未结束的同一批任务。该批次内部的调度器自动重试、账号分配和收尾动作不重复验证。用户手动继续、手动重试、进程重启后的恢复、新建批次或开始另一项远端核心操作时，必须重新验证。

## 业务流程

### 生成与分发

1. 管理员创建软件。
2. 管理员创建套餐并选择一款、多款或全部当前软件。
3. 管理员选择套餐、卡种、生成数量和可选默认备注。
4. 后台批量生成卡密，支持复制和表格导出。
5. 管理员可以逐张修改备注，并按卡密、备注、套餐、卡种和状态搜索筛选。

### 首次激活

1. 未找到适用本机授权时，客户端显示精简激活窗口。
2. 用户输入卡密，客户端计算稳定机器指纹哈希并请求激活。
3. 服务端确认卡密存在、尚未绑定或已绑定同一机器、套餐包含当前软件且软件已启用。
4. 未激活卡从服务器当前时间开始计算固定天数并绑定机器。
5. 客户端加密保存卡密和验证结果后进入软件。

客户端在首次发送激活请求前生成并持久化 `activation_request_id`（UUID）。同一次激活因超时或断网重试时复用该业务请求 ID，但每次传输使用新的时间戳和随机数。服务端按“业务请求 ID + 卡密 + 软件 + 机器”去重并返回相同结果；随机数只用于防止网络报文重放，不承担业务幂等职责。

### 日常验证

- 软件启动时验证一次。
- 开始转存、分享、刷新远端数据等核心远端操作前验证。
- 软件闲置时不请求服务器。
- 同一运行中批次的内部自动重试不重复验证，也不因授权状态变化强制中断；手动继续、手动重试、进程重启后恢复、新批次和新的远端核心操作必须重新验证。
- 服务器明确返回卡密不存在、已到期、机器不匹配、软件停用或套餐无权时，不得使用缓存继续操作。
- 只有连接失败、DNS/TLS 连接失败、超时、服务器 5xx 或 `429 rate_limited` 才允许使用仍在 30 分钟范围内的上次成功结果。
- 宽限过期后禁止开始新任务，但允许打开软件查看本地数据和进入设置中心。

### 续费、解绑与删除

- 续费把到期时间延长相应固定天数；未激活卡则增加首次激活后可获得的总天数。
- 解绑清除机器绑定和现有租约，不改变剩余有效时间；下一台电脑激活时继续使用原到期时间。
- 永久删除在单个事务中删除活动数据库里的卡密、绑定和服务端租约。之后所有在线验证立即返回卡密无效；已经签发到客户端的离线租约无法主动撤回，最多继续有效 30 分钟；已启动批次可完成，后续需验证的操作被拒绝。后台不提供恢复入口。

## 客户端接口契约

客户端请求包含协议版本、业务请求 ID、软件 ID、机器指纹哈希、时间戳和随机数。服务端签名响应至少包含协议版本、业务请求 ID、服务器时间、授权结论、稳定错误码和签名密钥 ID；成功响应还包含卡密 ID、软件 ID、机器哈希、到期时间和 `lease_until`。客户端必须核对请求 ID、软件 ID、机器哈希、时间窗口和签名后才能接受结果。

接口使用稳定的 HTTP 状态和机器可读错误码：

- `200 ok`：授权成功。
- `400 invalid_request`、`400 unsupported_protocol`：请求或版本错误，不允许离线宽限。
- `403 license_not_found`、`403 license_expired`、`403 app_not_allowed`、`403 app_disabled`：明确业务拒绝，不允许离线宽限。
- `409 machine_mismatch`：机器不匹配，不允许离线宽限。
- `429 rate_limited`：遵守 `Retry-After`；仅可继续使用尚未到期的本地租约。
- `500/502/503/504 service_unavailable`：仅可继续使用尚未到期的本地租约。

连接失败、DNS 失败、TLS 连接失败和超时按临时不可用处理；其他 4xx、响应签名错误、字段不匹配或服务器时间异常一律拒绝，不得降级宽限。服务端在可控情况下同时签名成功与业务拒绝响应；客户端只显示统一中文提示，不透出原始服务端错误。

### 保护性 429 协议修订（2026-09-09）

`200` 成功以及确定性的 `400/403/409` 是签名授权结论，客户端必须验证签名和完整 claims 后才可接受。限流在服务端读取或解析请求体之前执行；所有超限请求立即返回无签名的 `429`、`Retry-After`、`Content-Type: application/json`、`Cache-Control: no-store` 和唯一正文 `{"code":"rate_limited"}`，不承诺关联请求 ID，也不生成签名、占用重放随机数或调用授权服务。客户端必须先按 HTTP `429` 分支处理，再决定是否解析签名 envelope；该响应由 HTTPS 和客户端 TLS pins 保护，只表示临时限流，绝不授予授权，仅可继续使用尚未过期的既有本地租约。`5xx` 和传输失败同样是临时失败，未持有有效本地租约时不得放行；声称为 `200` 或确定性 `4xx` 的响应若签名无效则始终 fail closed。

## 后台界面

### 软件管理

显示软件名称、内部 ID、状态和套餐数量。允许新增、改名、停用和重新启用，不提供删除。

### 套餐管理

显示套餐名称和已选软件。管理员使用复选列表调整成员；保存后在客户端下一次在线验证时影响现有卡密。执行移除操作前明确显示会受影响的有效卡密数量，并提示离线客户端最长可能延迟 30 分钟生效。

### 卡密管理

顶部提供套餐、卡种、数量和默认备注，支持批量生成。列表包含卡密遮挡值、套餐、卡种、状态、激活时间、到期时间、绑定状态和备注，并支持：

- 搜索与筛选
- 复制单张卡密
- 批量导出
- 修改备注
- 续费
- 解绑机器
- 永久删除

永久删除需要二次确认，并明确显示“删除后无法恢复”。

### 设备绑定

按卡密查看机器指纹的短标识、绑定时间和最后成功验证时间。只提供管理员解绑，不显示或存储原始硬件信息。

## 客户端界面

未激活窗口只包含产品名称、卡密输入框、激活按钮、状态提示和关闭按钮。设置中心显示套餐、到期时间、授权状态和机器绑定状态，不显示续费入口或到期前提醒。

卡密无效时使用统一中文原因：

- 卡密无效
- 卡密已到期
- 该卡密未授权当前软件
- 当前软件已停用
- 卡密已绑定其他电脑，请联系管理员解绑
- 无法连接授权服务器，请检查网络后重试

客户端日志不得记录完整卡密、机器指纹、验证租约或后台内部错误。

## 安全与容量控制

- 所有公网请求必须使用 HTTPS，客户端同时内置当前与下一枚授权服务 SPKI 公钥指纹。证书切换前先通过 OTA 把下一枚指纹发布到所有仍受支持的客户端，并在确认最低受支持版本都已包含下一枚指纹后才切换服务端证书。旧证书及私钥的受控回滚包至少保留 90 天；需要回滚时重新部署旧证书。下一轮客户端再把新指纹设为当前指纹并预埋新的候选指纹。
- 验证结果由独立授权签名密钥签名，客户端内置对应公钥；不得复用 OTA 发布私钥。
- 激活和验证请求包含随机数与时间窗口，服务端拒绝明显重放。
- 卡密生成使用密码学安全随机数，显示格式便于人工复制但保留足够熵。
- 管理、激活和验证接口分别限流；失败采用指数退避并加入随机错峰。
- 普通验证不在每次请求同步写 `last_seen`；最后在线时间异步合并，最多每卡每小时写一次，避免 SQLite 写锁成为瓶颈。
- 卡密、套餐成员和软件状态使用索引查询；服务进程设置自动重启、超时、日志轮转和健康检查。
- 上线前使用生产同等 SQLite、加密和签名配置，在真实授权服务上分别以 50 和 100 请求/秒持续 10 分钟，固定流量比例为 70% 有效验证、10% 幂等激活、20% 明确业务拒绝；容量测试从 loopback 使用专用测试凭据绕过公网 IP 限流，限流行为另做独立测试。通过标准为：数据损坏为 0、SQLite `busy/locked` 为 0、排除故意无效请求后的 5xx/意外错误率低于 0.1%、p95 响应时间不高于 250 ms、CPU 平均低于 70%、可用内存始终高于 1 GB、服务 RSS 增长低于 10%，且健康检查持续返回 200。任一指标失败即阻止生产开放并先调优或降额。
- 卡密服务使用独立数据库、数据目录、系统用户和 systemd unit；部署/回滚不得改写现有 OTA 发布树或其他站点。
- 在卡密正式上线前完成 SSH 密钥登录、限制 root 密码登录和防扫描措施；不得在未验证密钥登录可用前关闭现有登录路径。

## 错误处理

- 明确业务拒绝不得降级为离线宽限。
- 网络失败只在本机存在未过期的成功租约时宽限，且界面显示当前使用临时授权。
- 激活请求重试必须幂等，同一卡密与同一机器重复激活返回相同授权状态。
- 套餐变更、续费、解绑和删除使用数据库事务；失败时不得留下部分状态。
- 客户端机器指纹读取失败时不得生成随机新指纹，应提示无法取得设备标识。

## 测试与验收

### 服务端

- 四种固定授权天数和服务器时间边界。
- 未激活卡连续续费能累计总授权天数，首次激活只计算一次到期时间。
- 首次激活请求 ID 幂等、传输随机数重放拒绝、超时重试返回同一结果。
- 机器冲突、解绑后重绑，以及删除后所有在线验证立即失败。
- 套餐新增/移除软件和软件停用在下一次在线验证生效，旧离线租约不超过 30 分钟。
- 软件停用只影响该软件。
- 续费基准、未激活续费和到期续费。
- 永久删除级联删除且不提供后台恢复入口。
- 管理接口认证、完整卡密精确检索、固定前 8 位/末 4 位索引筛选、备注包含搜索、加密密钥文件权限、日志脱敏、限流与重放拒绝。
- 每种 HTTP 状态与稳定错误码都返回符合契约的签名响应；字段、签名、时间异常不能触发离线宽限。

### 客户端

- 首次激活与同机多软件自动复用。
- 启动和每个核心操作前验证，闲置时零轮询。
- 明确拒绝不使用缓存；网络故障仅在 30 分钟内宽限。
- 运行中批次不强停，内部自动重试不验证；手动继续、手动重试、重启恢复和新任务重新验证。
- DPAPI `CurrentUser` 共享存储在同一 Windows 用户下跨软件复用；另一 Windows 用户输入同一卡时服务端识别为同机。
- MachineGuid、BIOS UUID 缺失或变化的指纹稳定性和管理员解绑路径；不得使用随机指纹降级。
- 卡密和机器信息不进入日志。

### 部署

- 卡密服务停止、重启和回滚不影响 OTA 稳定文件下载。
- Nginx 只暴露预定公开路径，内部管理端口保持 loopback。
- 部署前后复核现有 OTA 健康页、稳定版本、证书和其他站点基线。
- 真实客户端完成激活、跨软件复用、套餐动态变更、续费、解绑、删除和网络宽限验收。
- 真实接口按 70% 有效验证、10% 幂等激活、20% 业务拒绝的固定流量比例完成 50/100 请求每秒各 10 分钟压力测试，并全部满足本文错误率、延迟、CPU、内存、RSS、数据库锁和健康检查阈值后再开放生产使用。
- 使用当前/下一枚 SPKI 指纹演练证书切换与回滚，确认仍受支持的旧客户端不断授权。

## 明确不做

- 在线支付、自动售卡和订单系统
- 代理商、子管理员和客户账户
- 用户自助解绑
- 永久卡、试用卡、次数卡和并发席位授权
- 固定周期心跳或在线人数强制控制
- 离线激活文件
- 到期前弹窗提醒
- 卡密回收站
- 强制中断已经开始的批次
