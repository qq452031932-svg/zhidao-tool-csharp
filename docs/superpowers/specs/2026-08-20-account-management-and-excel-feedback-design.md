# 账号管理与 Excel 导入反馈设计

## 目标

在现有中文 WPF 应用中增加可见、可测试的账号管理入口，并修复用户选择 Excel 后界面无反馈的问题。

账号管理必须支持多个百度账号相互隔离：用户退出 B 时，A、C 保持登录且数据不受影响。退出 B 时只能二选一：保留 B 的历史记录，或清理 B 的全部历史记录。不存在全局“清理所有账号历史”的入口。

## 界面与交互

主窗口右上角保留“添加百度账号”，新增“账号管理”，并持续显示有效账号数量。

“账号管理”窗口使用数据库分页加载账号，不把大量账号一次性放入内存。每行只显示必要信息：账号显示名、登录状态、启用状态和“退出账号”。不显示百度用户 ID、Cookie、确认令牌、完整本地路径或请求信息。

点击某一行的“退出账号”后弹出二次确认，并要求选择：

1. “仅退出账号，保留历史记录”；
2. “退出账号，并清理该账号的终态任务历史”。

确认文案明确写出目标账号的显示名，并明确其他账号不受影响。操作完成后刷新账号列表、有效账号数量和创建任务向导的账号快照。失败时只显示稳定中文错误，不显示异常原文。

## 退出账号语义

复用现有 `RemoveAccountService` 的安全生命周期：先禁用账号并清除加密会话，再关闭 WebView2，安全删除该账号的独立浏览器目录，最后写入账号墓碑。账号行保留数据库墓碑以满足历史外键和防止同一百度身份被错误重复接管。

退出前必须检查两类未完成工作：该账号是否仍有 `Waiting`、`Reserved`、`Preparing`、`Submitting` 或 `ResultPending` 操作；该账号是否仍属于 `Queued`、`Active`、`Paused`、`AwaitingCandidates` 或 `PausedReady` 批次的 `AccountAllocations`。第二项覆盖成功目标模式中“已有分配但尚未动态生成操作”的情况。任一条件成立都拒绝退出，提示用户先完成、取消或重分配任务。预览和最终执行都必须检查。

最终检查、确认令牌复算、可选历史清理、账号禁用和 `EncryptedSession` 清空必须发生在同一个 SQLite `IMMEDIATE` 事务中。这样调度器不可能在检查通过后、凭据清除前再给 B 分配工作。现有 `RemoveAccountService` 需要拆成“事务内准备移除”和“事务后幂等关闭浏览器/清理目录/写墓碑”两个阶段；外部目录清理失败时账号仍保持禁用且无凭据，可在启动时或账号管理窗口中重试。

退出 B 不修改 A、C 的账号记录、会话、浏览器目录、配额或任务结果。

## 按账号清理历史

“清理终态任务历史”只作用于用户正在退出的账号，并且只处理终态任务数据。活动任务、待确认任务、结果待核对操作和导入草稿均不删除。确认窗口必须明确说明：共享批次的最小公共审计上下文和仍被其他账号使用的数据会保留，因此该选项不会宣称删除与 B 有关的每一个字节。

执行前返回只读预览：目标账号、可清理操作数量、受影响的终态批次数量、共享批次数量、将保留的共享上下文说明，以及确认令牌。先生成物化清理清单，再对清单的规范序列化做 SHA-256。清单必须包含目标本地 `AccountId`、稳定百度身份的单向指纹、账号状态、所有目标操作及状态/时间戳、分配成员与全部计数、候选资源归属字段与状态、批次全部字段、导入会话双向引用、所选清理模式。执行时在最终 `IMMEDIATE` 事务内重新生成完整清单并常量时间比较；目标账号不同，或分配成员、资源归属/状态、导入链接发生任何变化，都会使旧令牌失效并零写入。用户可见预览和日志不得显示身份指纹。

清理清单只能把终态批次中分配给 B 的终态操作列为目标。具体删除顺序在同一个 SQLite `IMMEDIATE` 事务中完成：

- 删除 `AccountId=B`、`TransferOperationId` 指向目标操作或 `ResourceItemId` 指向目标资源的执行日志；只有真正不绑定账号/操作/目标资源的批次级公共审计行可以在共享批次中保留；
- 删除该账号的终态 `TransferOperations`；
- 删除该账号在终态批次中的 `AccountAllocations`；
- 只删除“由已删除的 B 操作实际引用”或“明确 `CandidateConstraintAccountId=B`”且已无存活操作引用的资源；不能仅因资源当前没有操作就把公共成功目标候选判给 B；
- 若一个终态批次只属于该账号，先把 `ImportSessions.CreatedBatchJobId`、`ImportSessions.AppendToBatchJobId` 和 `BatchJobs.ImportSessionId` 置空，再删除依赖日志、批次图和对应已完成导入会话；
- 若批次还包含 A 或 C，则保留批次及其他账号数据，重新计算剩余资源数、操作数和汇总，不删除共享审计上下文；
- 提交前重新计算持久化批次计数和 A/C 账号统计，并要求 `PRAGMA foreign_key_check` 无结果；任一步骤失败都回滚。

同一事务完成可选历史清理、账号禁用和凭据清除后，再执行外部浏览器目录清理与墓碑终结。若事务失败，退出不开始；若浏览器目录清理进入 `CleanupPending`，数据库仍保持账号禁用且无凭据，并允许后续安全重试。

## Excel 导入无反馈修复

现有证据：用户选择文件后，数据库 `ImportSessions` 数量仍为零。根因已定位为 `ImportViewModel.RunImportAsync` 内仍使用 `adapterAvailability.CanStartTransfers` 做第二次提前返回；按钮外层虽已允许本地导入，这个内部旧门禁仍阻止工作流。修复必须从本地导入执行路径彻底移除转存可用性判断，创建任务和真实转存继续保留门禁。

导入界面增加明确状态机：

- 打开文件选择器时：“请选择 Excel 文件”；
- 用户取消时：“未选择文件”；
- 选择成功后立即显示脱敏状态：“已选择 Excel 文件，正在检查”；
- 创建导入会话后：“正在解析并写入草稿”；
- 导入中显示已处理行数；
- 完成后显示总计、就绪、重复、异常、排除、冲突和待解析数量；
- 失败只显示稳定中文错误码映射，不显示文件路径、工作表内容或异常原文。

文件选择结果、命令触发、工作流入口和数据库会话创建四个边界使用可注入接口与测试事件验证。真实 `OpenFileDialog` 仍封装在 `IDialogService`；ViewModel 不直接依赖静态对话框。导入层增加可注入进度契约，`ImportStagingService` 只能在每个 SQLite 分块事务提交成功后上报累计处理数；不能把尚未落库的枚举行数显示为已保存。`LocalImportWorkflow` 把该进度映射给 ViewModel，取消或失败不虚报。

文本和 Excel 导入属于本地草稿功能，不受“实际百度转存尚未通过现场门禁”的可用性开关影响。短链接需要在线解析时保留 `NeedsResolution`，不能伪装为就绪。

## 测试与验收

必须先写失败测试，再实现：

- 三账号中退出 B，A、C 的完整账号记录和会话字节不变；
- 两种退出模式分别保留或清理 B 的历史；
- 混合多账号批次只移除 B 的终态明细并保持 A、C 汇总一致；
- B 存在任一非终态操作时预览和执行都拒绝；
- 成功目标批次只有 B 的非终态 allocation、尚无 operation 时也拒绝退出；
- 陈旧确认令牌、事务中途故障、浏览器目录清理失败均不产生半删状态；
- A 的确认令牌不能用于 B，即使两者都没有历史清理行且账号状态相同；跨账号令牌必须零写入拒绝；
- 所有用户可见文案为中文且不泄露身份、Cookie、路径、链接或异常；
- Excel 取消选择、路径返回、工作流开始、进度、成功和错误均有明确状态；
- 对话框返回真实路径、转存可用性为 false 时，ViewModel 仍调用本地工作流并在真实 SQLite 创建导入会话；
- 真实 SQLite Excel 导入会创建会话并按 keyset 分页显示；
- 账号列表分页上限不超过 1,000，导入页维持现有每页 100 行和虚拟化；
- Release 严格编译、全量测试、数据库迁移/恢复测试和现场 WPF 操作通过。

## 非目标

- 不增加按日期清理；
- 不增加全局清理所有账号历史；
- 不删除或下载百度网盘云端文件；
- 不允许退出账号绕过未完成任务保护；
- 不在本阶段开放尚未通过现场验证的真实转存操作。
