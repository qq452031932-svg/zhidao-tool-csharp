# 按网盘账号拆分转存结果导出设计

## 目标

转存任务完成后，导出结果按参与的网盘账号拆分为独立 Excel 文件。每个账号在同一次导出中只生成一个文件，文件名使用账号显示名称和导出时间戳，例如 `美美哒152_20260912_143025.xlsx`。文件不覆盖历史导出。

## 数据与文件规则

- 结果按稳定的 `AccountId` 分组；账号显示名称只用于文件名和表内账号字段，避免同名账号被合并。
- 每个分组生成一个工作簿，不再为同一行横向追加多组“转存结果”列。
- 工作簿保留软件当前支持的标准字段（序号、标题、账号、分享链接、提取码、目标目录、状态、提示等）；不承诺保留用户自定义列。原“分享链接”和“提取码”单元格在成功时直接替换为本次生成的最新值，不新增“原链接/新链接”列，也不新增横向结果列。
- 未生成新链接的失败行保留原分享链接及原有字段，确保后续流程仍能按原名称和结构继续处理。
- 成功行同时写入新分享链接和新提取码；若新分享不含提取码则清空提取码，禁止新链接搭配旧提取码。
- 失败、跳过、待处理行进入同账号的“失败”文件，保留原分享链接和原提取码。
- 每个账号按结果类型最多生成两个文件：`账号名_成功_yyyyMMdd_HHmmss.xlsx` 与 `账号名_失败_yyyyMMdd_HHmmss.xlsx`；无对应记录的文件不生成。
- 文件名中的 Windows 非法字符替换为下划线，并限制长度；时间戳使用本地时间、格式 `yyyyMMdd_HHmmss`。
- 同一秒内发生重名时追加短序号，仍不覆盖已有文件。

## API 方向

新增按账号导出的应用服务，返回生成文件清单和每个文件的行数；保留现有单工作簿导出 API 以兼容旧调用，新的 UI 流程改用批量导出 API。基础 OpenXML writer 接收单账号行集合，因此不负责账号分组和文件命名。

## 错误处理

- 账号名称为空、非法或过长时使用安全的降级文件名，不把路径或异常正文写入结果表。
- 任一账号文件写入失败时保留已成功生成的文件，并返回每个账号的成功/失败状态；不删除用户已有历史文件。
- 取消操作时不覆盖已有文件，当前临时文件清理或保留为可识别的 `.partial` 文件。

## 测试范围

- 分组：1 个账号生成 1 个文件，多个账号生成多个文件。
- 命名：账号名、时间戳、非法字符和同秒冲突处理。
- 内容：每个工作簿只有一组结果列，不产生横向重复列；最新分享链接写入正确。
- 安全：账号名不能路径穿越，输出目录之外不可写。
- 回归：现有单工作簿导出测试继续通过。
