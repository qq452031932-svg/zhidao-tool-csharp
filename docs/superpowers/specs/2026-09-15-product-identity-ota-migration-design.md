# 知道综合工具：程序实体改名、图标与 OTA 迁移设计

日期：2026-09-15  
目标版本：1.1.1（迁移版本）

## 1. 目标

将 Windows 客户端的真实主程序从 `BaiduBatchTransfer.App.exe` 改为 `知道综合工具.exe`，并使用用户提供的头像图片作为应用、任务栏、快捷方式和安装包图标。用户可见名称统一为“知道综合工具”。

这次变更必须同时满足：

- 已安装 1.1.0 的用户可以通过现有在线更新通道升级到 1.1.1；
- 百度账号、任务数据库、设置和卡密状态不丢失；
- 不更换线上更新地址，不破坏已经发给用户的固定下载链接；
- 不清理或覆盖服务器上的其他项目；
- 1.1.1 经本地迁移验收后才允许发布到生产环境。

## 2. 稳定身份与可变品牌

### 必须保持不变

- Velopack 包 ID：`SuperPan.BaiduBatchTransfer`
- 更新通道：`win-x64-stable`
- 更新源：`https://ota.fanfh.cn/releases/win-x64/stable/`
- 固定安装包地址：`SuperPan.BaiduBatchTransfer-Setup.exe`
- 本地数据目录：现有 `%LOCALAPPDATA%\BaiduBatchTransfer` 路径
- 单实例互斥体：现有 `Local\BaiduBatchTransfer.Singleton.v1`
- 卡密产品 ID：`8270e8d7-1791-487d-ad76-0da7a0cbed12`
- 卡密签名密钥标识、服务端协议和已有授权数据

这些值是兼容性身份，不是用户可见品牌。保留它们可以避免用户被当作安装了一个全新软件，也避免数据库、账号和授权状态被重新初始化。

### 本次改变

- .NET 程序集名和物理主程序名：`知道综合工具`
- 物理主程序：`知道综合工具.exe`
- 产品标题、文件描述、安装器标题和快捷方式名称：`知道综合工具`
- 主程序、窗口、任务栏、快捷方式和安装器图标：用户提供的头像
- 发布脚本和验收器中的主程序名从硬编码改为唯一的、受测试约束的品牌常量

## 3. 图标处理

来源是用户提供的 640×640 JPG：

`C:\Users\45203\AppData\Local\Temp\codex-clipboard-178c6012-31da-4e0a-a819-dc3a12c2756c.jpg`

不使用生成式重绘。构建资源中保存一份规范化 PNG 和一份多分辨率 ICO；ICO 至少包含 16、24、32、48、64、128、256 像素层级。转换只做尺寸适配和格式封装，不改变人物内容。

项目通过 `ApplicationIcon` 写入 PE 图标，并给 WPF 主窗口/激活窗口指定同一资源。Velopack 打包时同时传入 `--icon` 和 `--packTitle`，覆盖安装器、卸载项及快捷方式展示。

## 4. 升级迁移策略

### 1.1.1 是一次过渡发布

1.1.1 的正式主程序是 `知道综合工具.exe`，Velopack 的 `--mainExe` 指向它。为防止旧版快捷方式、旧启动桩或升级后的重启过程仍引用 `BaiduBatchTransfer.App.exe`，1.1.1 包中暂时保留一个极小的兼容启动入口 `BaiduBatchTransfer.App.exe`。

兼容入口只负责：

1. 在同一安装目录定位 `知道综合工具.exe`；
2. 使用 `ProcessStartInfo.ArgumentList` 原样转发参数，保留工作目录，不拼接命令行；
3. 普通用户启动时，成功创建新进程后退出；
4. 遇到 Velopack 生命周期或迁移参数时，同步等待新进程退出并返回其退出码，避免更新器与生命周期钩子竞态；
5. 找不到新主程序时显示明确错误，不下载、不修复、不修改用户数据。

它不包含业务代码，也不创建第二套数据目录。新安装、更新重启以及新快捷方式都必须直接指向 `知道综合工具.exe`。

兼容入口必须由与正式主程序相同的 Authenticode 发布者签名。它只能启动同一受信安装树内的中文主程序；解析后的目标路径必须位于预期目录，且必须拒绝目录逃逸和不受信的重解析点目标。发布验证器检查入口的签名、发布者 SPKI、目标架构和转发行为。

### 根启动器和快捷方式迁移门

项目当前固定使用的 Velopack 版本不能被假定为能够安全处理主 EXE 改名。开始产品代码改动前，先制作最小的两个版本样例，以当前 Velopack 版本真实安装旧版并升级到改名版，记录并检查：

- 安装根目录的启动器文件名和目标；
- `current` 目录的主程序；
- 桌面和开始菜单快捷方式名称、图标与目标；
- 更新完成后的自动重启目标；
- 卸载项显示名称和图标。

若当前版本不能正确迁移，必须先选择并验证包含相关改名修复的 Velopack 版本，或实现显式且幂等的快捷方式/根启动器迁移钩子。生产实现不得只根据 `--mainExe` 推断迁移已经成功。

### 后续清理

兼容入口默认在后续版本长期保留。只有建立了明确的最低可升级版本门槛，并能证明所有仍受支持的旧版本都已使用中文入口后，才允许通过独立设计和测试移除。否则每个后续版本都必须覆盖 `1.1.0 → 当前版本` 的直接跨版本升级。

不选择“一次发布直接删除旧 EXE”的原因：如果 Velopack 根启动桩、旧快捷方式或升级重启参数仍持有旧文件名，用户可能更新成功却无法再次启动。兼容入口不改变真正主程序已经改名的结果。

## 5. 构建与发布脚本

建立单一品牌配置，至少包含：

- `ProductDisplayName = 知道综合工具`
- `MainExecutableName = 知道综合工具.exe`
- `LegacyExecutableName = BaiduBatchTransfer.App.exe`（用于迁移兼容，持续到满足最低可升级版本门槛并通过独立移除设计为止）

生产和验收打包统一使用新主程序名，并向 Velopack 传递：

- `--mainExe 知道综合工具.exe`
- `--packTitle 知道综合工具`
- `--icon <规范 ICO 路径>`

包文件名与固定下载别名继续使用 `SuperPan.BaiduBatchTransfer-*`，以保持已经发出的 URL 有效。所有含中文路径的脚本调用必须按参数数组传递，禁止拼接未加引号的命令字符串。

设置程序集名后，元数据程序集也会从 `BaiduBatchTransfer.App.dll` 变为 `知道综合工具.dll`。项目目录、代码命名空间和 `InternalsVisibleTo("BaiduBatchTransfer.App.Tests")` 保持英文不变；产物路径、反射加载路径、WPF pack URI、测试夹具、授权边界脚本和 OTA 验证器中的旧 EXE/DLL 硬编码必须逐一审计。PE 元数据显式设置并验证 `AssemblyTitle`、`Product`、`Description`、`FileVersion` 和 `ProductVersion`。

发布资产验证器同时检查：

- Full 包的 `lib/app/知道综合工具.exe` 存在；
- 便携包和安装后的 `current/知道综合工具.exe` 存在；
- 1.1.1 迁移包包含兼容入口；
- 新主程序的产品名称、文件描述、版本和图标正确；
- 新安装的快捷方式不再指向旧入口；
- 安装根目录存在且可运行 `知道综合工具.exe`，而不只检查 `current` 子目录；
- 固定安装包 URL 和包 ID 没有变化。

## 6. 卡密到期时间

现有本地实现已经在主界面授权状态区域显示授权状态和到期时间，激活成功后刷新，并在启动时从本地授权状态加载。该功能不因程序集改名而改变；1.1.1 验收中必须再次覆盖：

- 未激活显示“未激活”；
- 有截止时间的授权显示明确的本地日期时间；
- 永久授权显示“永久”；
- 从 1.1.0 升级后仍读取同一份授权状态，不要求用户重新激活。

## 7. 验收方案

### 自动测试

- 项目结构测试：程序集名、输出 EXE 名、图标资源、产品元数据正确；
- 发布脚本测试：新 `mainExe`、标题、图标参数存在，旧包 ID/通道/固定别名不变；
- 包内容测试：新主程序和 1.1.1 兼容入口均存在且职责分离；
- 兼容入口测试：参数正确转发，目标缺失时安全失败；
- 原有卡密、历史清理、任务导入和 OTA 安全测试全部回归。

### 隔离的真实升级测试

真实 Release 包不接受 Debug 的自定义数据目录参数，因此迁移验收必须在一次性 Windows VM、Windows Sandbox 或独立的临时 Windows 用户配置文件中执行；仅换安装目录不算隔离。真实 Release 授权保留验收必须使用由生产信任链签发、仅供隔离验收的专用测试卡密或授权，不手写伪造状态。创建或消耗这类测试卡是单独、可审计的服务端测试动作；接受环境授权只能用于辅助测试，不能替代真实 Release 授权保留验收。验收前后记录宿主机生产用户目录未被触碰的证据。

在上述隔离环境中，Setup 安装态分别完成两条路径：

- `1.1.0 full + 1.1.1 delta`；
- 禁用或移除 delta 后的 `1.1.0 → 1.1.1 full` 回退路径。

如果 Portable 继续作为正式资产提供，还必须单独验证其 `1.1.0 → 1.1.1` 更新、根启动器和更新后重启。Portable 不创建系统快捷方式时，其结果不得替代 Setup 的桌面/开始菜单快捷方式验收。

每条路径均执行：

1. 按当前路径安装或展开线上同构的 1.1.0；
2. 写入可识别的账号、设置、任务和本地授权测试状态；
3. 从本地签名候选源发现并下载 1.1.1；
4. 执行更新并重启；
5. 验证实际运行的是 `知道综合工具.exe`，新图标生效；
6. 验证原数据和授权到期时间仍可读取；
7. 验证安装根目录中文启动器、旧兼容入口、新快捷方式和更新后自动重启均指向正确目标；
8. 验证兼容入口的签名、发布者、架构、生命周期等待/退出码和路径约束；
9. 验证回退/失败不会清空原安装与数据。

测试不得写入生产 OTA 目录，不得操作服务器上其他项目。

### 生产在线更新测试

只有本地迁移验收全部通过后，才生成 1.1.1 正式签名上传包。上传生产环境是单独的外部变更步骤，执行前再次核对服务器目标目录和资产清单；只处理该 OTA 发布目录内由清单列出的文件，不删除服务器其他内容。

发布采用 staging + 原子切换：先上传到同一文件系统的 staging 目录，核对每个文件的大小、SHA-256、签名和清单引用，再原子切换 feed 与固定别名。保留旧版本 full 包和切换前后清单。失败时只回退 feed/别名，不删除历史版本或服务器上的其他项目。已经安装 1.1.1 的客户端不依赖降级 feed 回退；如上线后出现问题，发布更高版本号的热修复。

上线后按以下路径验收：

1. 使用真实 1.1.0 客户端点击检查更新；
2. 确认发现 1.1.1；
3. 下载、安装并自动重启；
4. 确认进程和主程序名为 `知道综合工具.exe`；
5. 确认图标、账号、任务记录与授权到期时间正确；
6. 用固定安装包链接做一次全新安装验证。

生产发布前不伪造“在线更新已验证”的结论。

## 8. 完成标准

- Debug/Release/生产等价构建均输出 `知道综合工具.exe`；
- Windows 资源管理器、任务栏、窗口、快捷方式、安装器/卸载项显示新名称和新图标；
- 1.1.0 → 1.1.1 隔离迁移真实通过；
- 数据目录、包 ID、卡密产品 ID与固定下载地址不变；
- 卡密到期时间回归通过；
- 全量自动测试无新增失败；
- 生成可审计的 1.1.1 上传包和上线验收说明，但未经明确上线步骤不改生产服务器。
