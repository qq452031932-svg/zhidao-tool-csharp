# 转存后自动分享与链接替换设计

## 目标

在现有百度批量转存应用中增加一条受控流水线：导入带标题和其他业务字段的 Excel 数据，按用户明确选择的账号与分配策略完成转存，对每个实际转存结果创建百度永久分享，并把新链接、提取码和状态写入另存的结果 Excel。

源标题与网盘文件或文件夹名称相互独立。用户导入的标题、关键词、简介及其他原始列内容必须原样保留，不因转存结果名称而变化。只有导入记录缺少标题时，才读取原分享中显示的资源名称作为备用标题；多个顶层项目使用“第一个资源名称 等 N 项”的稳定备用格式。

本功能对标 PanTools 的“转存后分享＋替换链接”操作，但只实现本产品需要的批量转存和转存后分享，不扩展为通用网盘管理套件。参考：[PanTools 替换链接教程](https://pantools.52king.vip/253.html)。

## 已确认的产品决策

- 使用“转存并替换链接”一体化流水线，不开发独立的通用批量分享页面。
- 原 Excel 永不修改；每次导出都另存带时间戳的新 `.xlsx` 文件。
- 导入后先显示列对应确认，由系统自动识别并允许用户调整。
- 所有原始数据列的内容原样保留，但不复制背景、图片、复杂公式等装饰格式。
- 每条导入链接对应一个逻辑资源；不区分它是文件、文件夹、APK、压缩包或多个顶层项目。
- 新分享必须指向该链接实际转存得到的同一组顶层内容，不额外套标题目录、不改名。
- 分享默认永久有效、访问人数不限制。
- 提取码在创建任务时选择随机生成或全任务统一指定。
- 多账号复制时，每个参与账号分别创建自己的分享链接。
- 多账号输出采用“一条资源一行、每个账号一组列”。
- 原链接作为独立列在所有结果行中保留，便于核对和失败排查。
- 每个“账号＋实际网盘资源集合”默认只创建一次分享；发现已有分享时先询问复用、重新生成或取消。
- 重新生成分享不会自动取消旧分享，避免破坏正在使用的链接。

## 范围边界

### 本期范围

- Excel 列自动识别、用户确认与数据预览；
- 源标题、原链接、提取码及其他原始列的流式导入；
- 用户选择参与账号、转存模式和账号分配规则后的精确工作量预览；
- 转存成功后对实际转存资源创建永久分享；
- 已有分享检测、复用与用户确认后重新分享；
- 分阶段进度、失败隔离、断点恢复和结果待确认；
- 另存多账号动态列结果 Excel；
- 分享失败记录单独重试，不重复已成功转存。

### 非目标

- 扫描网盘任意文件的通用批量分享管理；
- 批量取消已有分享；
- 批量重命名、广告文件清理、链接监控、群发或自动回复；
- 其他网盘支持；
- 复制源 Excel 的图片、样式、宏、公式和复杂版式；
- 未经用户选择，让所有已登录账号自动参与任务。

## 导入与列对应确认

选择 Excel 后先读取有界样本并显示“列对应确认”窗口。系统根据表头别名和单元格内容自动建议：

- 源标题列；
- 原分享链接列；
- 原提取码列；
- 其他原样保留列。

窗口显示前 20 行安全预览。链接列必须明确确认；标题和提取码可以为空。没有标准表头时，系统可根据百度分享 URL 特征识别链接列，并建议左侧最近的非链接文本列为标题列。任何自动建议都可由用户修改，确认前不创建正式任务。

导入必须继续采用流式 OpenXML 读取和分块 SQLite 提交。不得为了保留原始列而把完整行集合放入内存。需要为每个导入会话保存有序列定义和每行原始文本值，输出时再按会话列定义重建整洁的新工作簿。所有文本写入继续使用公式注入防护。

粘贴文本导入没有标题时，预检阶段可读取分享显示名称作为备用标题；用户输入的标题始终优先。

## 账号选择与工作量计算

已登录账号只构成可选账号池。创建任务时必须先让用户确认：

- 哪些账号参与本任务；
- 使用单账号、分流还是多账号完整复制；
- 每个账号的配额或目标；
- 哪些参与账号需要创建分享。

所有工作量都从最终确认的资源到账号分配关系计算，不从已登录账号数量推算：

- 20 万资源、登录 10 个账号但只选 A：20 万次转存、20 万次分享；
- A/B/C 分流处理 20 万资源：总计 20 万次转存、20 万次分享；
- A/B/C 各自完整复制 20 万资源：60 万次转存、60 万次分享；
- Excel 逐行指定账号：按每行实际映射计算；
- 参与转存但取消勾选分享的账号：只计算转存，不创建分享。

任务确认页展示每个参与账号的转存数量、分享数量、配额或成功目标、预计总操作数和分享设置。其他已登录账号明确显示为“不参与”，未经用户确认不得创建任务操作。

## 转存与分享流水线

每个“源资源＋参与账号”使用两段持久化状态：

1. 转存阶段；
2. 分享阶段。

转存成功响应必须持久化实际保存到该账号中的远端资源 ID 集合。分享阶段只能使用这组精确 ID，不能通过标题、文件名或目标目录猜测。一个源链接包含多个顶层项目时，使用一个百度分享包含这组实际保存项目；单文件和单文件夹同理。

分享请求设置：

- 有效期：默认永久有效；
- 访问人数：不限制；
- 提取码：任务随机生成或任务统一指定；
- 分享范围：该条导入记录在该账号中的全部实际转存顶层资源。

当百度要求验证、账号登录失效或不允许当前分享设置时，只暂停该账号并显示稳定中文状态，其他账号继续执行。系统不得偷偷把永久分享降级为短期分享。

## 防重复与结果核对

分享身份以本地账号 ID 和规范化的实际远端资源 ID 集合为基础，并绑定分享设置与生成代次。系统持久化百度分享 ID、新 URL、新提取码、创建时间和当前有效状态。

执行前发现同一账号对同一资源集合已有仍有效分享时，先显示汇总确认：

- 复用已有分享（默认）；
- 重新生成分享；
- 取消本次任务。

用户选择重新生成时创建新代次，但不自动取消旧分享。对于网络中断或百度响应不明确的创建请求，状态进入 `ResultPending`；先查询该账号的已有分享并按请求描述符、资源集合和时间边界核对，确认不存在后才能再次创建。不能用盲目重试制造重复分享。

## 状态、重试与恢复

转存状态至少包括：等待、已保留、准备中、提交中、结果待确认、成功、失败、暂停。

分享状态至少包括：等待转存、等待分享、分享中、结果待确认、成功、失败、暂停、复用已有。

处理规则：

- 转存失败不进入分享阶段；
- 转存成功但分享失败时只重试分享；
- 瞬时网络错误最多自动重试 3 次，并遵守百度返回的等待时间；
- 明确的登录、容量、路径或验证错误按账号隔离；
- 分享响应不明确时保留结果待确认，不释放会导致重复生成的账号资源锁；
- 软件关闭、进程崩溃或电脑重启后，从持久化状态恢复；
- 已成功转存或分享的工作不得因恢复而重复执行；
- 任务执行中和终态后均可流式导出当前结果。

## 结果 Excel

输出文件默认命名：`原文件名_转存分享结果_yyyyMMddHHmmss.xlsx`。源文件保持不变。

结果按“一条源资源一行”输出：

1. 所有原始数据列，按原顺序保留文本内容；
2. 独立的“原链接”列，所有记录均填写；
3. 每个本任务参与账号的一组动态列：
   - `<账号显示名> 新分享链接`；
   - `<账号显示名> 提取码`；
   - `<账号显示名> 分享状态`。

账号列顺序与任务确认页的账号顺序一致。账号显示名经过安全清洗；同名账号使用稳定的非敏感序号区分。

单账号任务只追加一组列。多账号分流任务中，每行只填写实际负责该资源的账号列，其他账号列留空。多账号复制任务中，每个参与账号的结果分别填写。

分享成功或复用已有时填写新链接与提取码。分享失败时新链接和新提取码留空，状态写入稳定中文结果；原标题、所有原始列和原链接仍完整保留。结果文件不显示 Cookie、百度用户 ID、确认令牌、请求头、内部资源 ID 或异常原文。

Excel 行数超过单工作表限制时自动分工作表，并在每张表重复表头。导出采用 keyset 分页和流式 OpenXML 写入。

## 界面

### 列对应确认

显示字段映射、前 20 行预览、可保留列清单和确认按钮。路径和内容只在该明确数据视图中显示，不进入全局状态栏或日志。

### 创建任务

在现有账号选择和分配步骤之后增加“转存后自动分享”设置：

- 默认开启；
- 永久有效；
- 不限制访问人数；
- 随机提取码或统一指定；
- 每个参与账号可单独取消分享；
- 已有分享处理为“执行前询问”。

确认页展示精确的每账号转存与分享数量、总数和输出格式。预览令牌必须绑定账号选择、分配结果、分享设置、列映射和输出账号顺序；任何变化都使旧确认失效。

### 任务进度与导出

当前页只加载有界结果。用户能分别看到转存与分享状态、账号级暂停原因和可重试数量。提供“重试分享失败项”和“另存替换结果”操作。分享失败重试不得重新执行已成功转存。

## 数据与安全

新增持久化信息至少包括：

- 导入列定义和每行保留的原始文本值；
- 每个账号的实际转存远端资源集合；
- 分享请求描述符、分享状态、结果 ID、URL、提取码和生成代次；
- 已有分享复用决策和用户确认快照；
- 转存与分享分别的尝试计数和最后稳定错误码。

分享 URL、原链接和提取码属于用户数据，只能在明确的草稿、结果和导出视图中显示。普通日志仅记录结构化阶段、稳定错误码和计数。Cookie、完整会话、百度用户 ID、内部确认令牌、请求头、响应正文和本地 profile 路径不得进入日志或结果文件。

所有 SQLite 写入使用参数化语句。提交边界、响应 ID 和结果持久化顺序必须延续现有转存调度器的防重复语义。账号退出和历史清理必须识别未完成分享操作，不能在分享提交或结果待确认期间清除账号会话。

## 性能与容量

- 支持至少 20 万源资源；
- 账号工作量按实际分配边流式生成，不能预先物化数百万完整对象；
- 导入、预览、调度、分享结果查询和导出均使用 keyset 分页；
- UI 单页上限不超过 1,000，默认维持较小页面；
- 动态账号列只影响输出列数，不把所有行放入内存；
- 创建任务前磁盘估算包含分享操作、分享结果、索引和 WAL 增长；
- 账号数量和 Excel 最大列数必须在预览时校验，超过安全上限时拒绝确认并给出中文说明。

## 测试与验收

实现必须使用测试驱动开发，并覆盖：

- 不同表头和无表头 Excel 的自动识别、人工调整和前 20 行预览；
- 原标题、关键词、简介和任意其他原始文本列逐字保留；
- 用户标题优先、缺标题时资源名回填、多顶层项目备用标题；
- 单文件、文件夹、APK、压缩包和多顶层项目都只产生一个对应分享；
- 分享使用实际转存资源 ID，不按标题或目录猜测；
- 登录 10 个账号但只选 1 个时，20 万资源只生成 20 万转存和 20 万分享；
- 三账号分流 20 万仍是 20 万总量，三账号完整复制才是 60 万；
- 每个账号可独立关闭分享，确认页与实际操作数量一致；
- 分享成功、失败、响应不明确、登录失效和验证暂停；
- 转存成功后分享失败只重试分享；
- 进程在转存提交前后、分享提交前后和结果持久化前后死亡时正确恢复；
- 同账号同资源已有分享时必须询问，复用不创建新分享，重新生成创建新代次且不取消旧链接；
- 旧确认令牌在账号选择、分配、分享设置或列映射变化后拒绝且零写；
- 单账号、分流和复制三类动态列结果正确；
- 分享失败行保留所有原始列和原链接，新链接留空；
- 超过 Excel 行限制时分工作表，所有用户文本执行公式注入防护；
- 20 万行流式导入和导出维持有界托管内存；
- 日志、错误弹窗、`ToString()` 和诊断包不泄露链接、提取码、Cookie、用户 ID、确认令牌或响应正文；
- Release 严格编译、全量回归、数据库迁移/恢复测试和百度现场验收通过。

## 现场验收门禁

自动化测试不能代替百度真实页面和账号限制。发布前必须使用仅由用户控制的测试账号完成：

1. 单文件、文件夹和多个顶层项目的转存后永久分享；
2. 随机与统一提取码；
3. 单账号、分流和多账号复制；
4. 已有分享复用与重新生成提示；
5. 登录失效、百度验证和响应不明确后的恢复；
6. 结果 Excel 中原标题、原链接和各账号新链接的对应关系。

现场验收不得绕过验证码、安全验证、访问限制或百度风控。
