# 本地浏览器自动化迁移设计

日期：2026-08-26  
状态：规格审阅已通过，待用户确认

## 1. 已确认的决定

百度转存与分享的网页执行层由内嵌 WebView2 改为本机可见的 Chromium 浏览器。首选 Google Chrome，Microsoft Edge 作为兼容选择。程序不接管用户日常使用中的默认浏览器资料，而是为每个百度账号建立独立的自动化资料目录。

现有的导入、草稿、账号管理、任务分配、批次调度、数据库、失败重试、结果展示与导出模块继续保留。迁移只替换“实际打开并操作百度网页”的执行边界，因此前期完成的业务模块不会废弃。

本设计取代 `2026-08-24-two-workspace-webview-automation-design.md` 和 `2026-08-26-webview2-candidate-protocol-design.md` 中关于“新操作必须使用 WebView2 执行”的部分；其中关于 exact-ID、提交前证据、一次性写授权、持久化提交边界、只读恢复和安全日志的约束继续有效。其他既有业务规格不变。

## 2. 目标

- 用户登录一次后，后续转存与分享复用同一账号的浏览器登录状态。
- 转存和分享使用同一套本地浏览器管理、页面等待、错误处理与人工接管能力。
- 浏览器必须可见；验证码、风控或页面异常时允许用户直接处理。
- 单条资源可以完成“打开分享链接 → 输入提取码 → 转存指定文件或文件夹 → 可选自动分享 → 返回分享结果”。
- 后续增加页面操作时，只扩展浏览器动作和页面适配器，不修改任务调度与数据库主流程。

## 3. 非目标

- 不调用百度开放平台接口。
- 不导出、复制或上传浏览器 Cookie。
- 不接管用户正在使用的个人 Chrome/Edge 默认资料目录。
- 不绕过验证码、登录保护、限流或百度的安全验证。
- 本阶段不同时重写转存与分享的业务调度模块。

这里的“不导出 Cookie”是指 helper、C# 进程和 IPC 都不得读取或传递 Cookie 值。浏览器可以在自己的专用资料目录中正常保存登录状态。旧 `AccountSession` 的 Cookie 会话仅供旧执行引擎完成已开始的旧操作，不能注入新浏览器资料目录。

## 4. 浏览器发现与用户选择

启动时按以下顺序确定浏览器：

1. 使用用户上次成功选择并保存的浏览器可执行文件路径。
2. 检查少量固定安装位置，不进行全盘递归扫描。
3. 若未找到、路径失效或快速检查超时，立即弹出文件选择窗口。

文件选择窗口只允许选择 `chrome.exe` 或 `msedge.exe`。选择后通过已打开的文件句柄取得最终规范路径，拒绝重解析点和路径替换；验证 Authenticode 签名链、允许的发布者（Google LLC 或 Microsoft Corporation）和产品身份。不得以裸启动用户所选程序作为真实性验证。

保存配置时同时保存浏览器家族、规范路径、发布者、产品身份和文件身份。每次启动前重新验证文件签名与身份，防止选择后被替换。若需要兼容性启动探测，只能使用新的临时受管 Profile、随机回环端点和 Job Object；探测结束后确认进程退出，再安全清理临时目录。界面提供“重新选择浏览器”，用户可以随时替换已保存路径。

“重新选择”只修改以后新建的浏览器会话。已经开始或正在恢复的操作不能因此切换浏览器家族或执行引擎。

## 5. 账号与浏览器资料目录

- 每个百度账号对应一个独立资料目录和一个浏览器进程。
- 数据库新增无 Cookie 的 `ManagedBrowserSessionReference`，至少绑定 `AccountId + StableBaiduUserId + BrowserFamily + ProfileId + ProfileOwnershipId`。业务调度只携带该引用，不携带 Cookie。
- 资料目录位于应用自己的本地数据目录内，不使用浏览器默认个人资料目录。
- 同一账号的转存和分享复用该资料目录；不同账号之间完全隔离。
- 同一账号同一时间只允许一个写操作，避免窗口和目录状态相互干扰。
- 资料目录被占用、损坏或浏览器异常退出时，任务进入可恢复状态，不自动删除登录数据。
- Chrome 与 Edge 使用不同资料目录。切换浏览器家族时必须创建新资料目录、重新登录并核对稳定百度 UID，禁止直接复用原资料目录。
- 旧账号第一次迁移时必须在新资料目录重新登录。UID 与账号记录一致后才能建立引用；旧 Cookie/WebView2 Profile 只作为旧引擎回退材料保留。
- 账号删除前先停止该账号的受管浏览器并确认没有在途操作，再删除会话引用。资料目录默认隔离到可恢复区，由用户明确确认后再清理。
- 资料目录以不透明账号 GUID 派生，设置为当前 Windows 用户可访问；创建与打开时验证 ownership token、规范路径、重解析点和目录边界。

应用层新增有明确引擎分支的 `BaiduExecutionContext`：

- `LegacyWebView2Context` 只供 `WebView2-v1` 使用，内部引用现有 `AccountSession` 和旧 Cookie store。
- `ManagedChromiumContext` 只供 `ManagedChromium-v1` 使用，内部引用 `ManagedBrowserSessionReference`，不得读取 `IBaiduSessionStore`、旧 Cookie 或 WebView2 Profile。
- 调度器按持久化的执行引擎解析且只创建其中一种 context；适配器不得在运行时自行回退到另一种 context。

`IBaiduNetdiskAdapter`、`IOperationBoundBaiduNetdiskAdapter`、`IBaiduShareAdapter` 和相关协调包装器的账号参数迁移为 `BaiduExecutionContext`，或在过渡期由两个明确分离的引擎专用接口实现。账号验证、容量刷新、目录读取、分享检查、转存和分享都必须走同一引擎 context；新引擎的只读能力也通过受管浏览器完成。

受管浏览器未启动时返回可恢复的 `BrowserUnavailable`；未登录或登录过期时返回 `LoginRequired` 并暂停该账号；稳定 UID 缺失或不匹配时返回 `AccountIdentityMismatch`、禁止任何写动作并要求重新登录。上述结果进入现有有类型错误/调度决策，不得伪装成空目录、零容量或成功。

## 6. 本地浏览器控制方式

优先复用 `D:\自动分享` 中已经验证过的“本机 Chrome + 独立 `user-data-dir` + 本地调试端口”模式，并将其封装为当前 C# 应用可调用的浏览器执行适配器。

- 调试服务只绑定本机回环地址；同一 Windows 用户下的其他本地进程仍可能访问调试端口，这是明确接受的残余风险，程序不得把调试端口暴露到局域网或公网。
- 程序使用浏览器随机端口能力，并从私有资料目录中的 `DevToolsActivePort` 读取实际端点；不得先挑固定端口再仅以“端口已开放”判断归属。
- 程序启动浏览器后记录根进程 PID、可执行文件身份、浏览器家族、资料目录、ProfileOwnershipId 和 BrowserId，并通过 Windows Job Object 管理子进程。连接时必须同时核对这些值。
- 每次任务绑定明确的 TargetId；旧标签页、用户新开的标签页和其他百度标签页均不能自动成为任务目标。
- 浏览器关闭后可重新启动并重新连接同一账号资料目录。
- 浏览器版本或连接协议不兼容时显示明确提示，并允许重新选择 Chrome/Edge。

第一阶段参考 `D:\自动分享` 中的页面适配经验，抽取一个新的最小 Python/DrissionPage helper；不得把原项目整体打包进产品。helper 不提供 HTTP 服务、不保存独立任务状态、不负责业务重试、不直接导出最终结果，也不沿用可能包含网页数据的旧日志。

helper 随应用自包含发布，固定 Python、DrissionPage 及传递依赖版本，并记录许可证。helper 文件清单、版本和 SHA-256 哈希嵌入受签名的 C# 发布物；每次启动前逐文件验证，任何缺失、篡改或版本不符都拒绝启动。目标电脑不要求用户另外安装 Python。

C# 仍是数据库、调度、账号绑定、一次性写授权、恢复和最终结果导出的唯一负责人。C# 与 helper 默认使用由父进程创建的私有标准输入/输出或匿名管道，不开放监听端点。若平台原因必须使用命名管道，则要求随机管道名、当前用户 ACL、一次性 nonce、helper PID/父进程 PID 绑定和首包协议版本认证。

协议使用带版本的长度帧 JSON，只允许固定动作和固定结果类型，并规定消息上限、CorrelationId、操作 ID、账号 ID、代次、超时、取消、乱序/迟到/重复响应和子进程崩溃语义。stdout 只承载协议帧，非协议输出视为 helper 故障；stderr 只能输出固定脱敏事件码。协议不得传递任意脚本字符串。后续若改为 C# 浏览器驱动，只替换 helper 实现，不改变该有类型接口。

## 7. 转存流程

1. 调度器选出一条资源和账号，生成当前操作代次。
2. 浏览器管理器启动或连接该账号的专用浏览器。
3. 打开导入的百度分享链接；存在提取码时自动填写。
4. 完整读取分享页顶层对象的 exact-ID 集合、对象类型、服务端名称、稳定百度 UID、分页结束证据和页面 generation token，并与导入资源绑定。一个链接有多个顶层对象时，作为一个 exact set 整体处理。
5. 打开保存目录选择界面；按账号配置创建或进入目标目录。
6. 点击转存前保存目标目录 exact ID、完整目标基线、generation token 和观察指纹；每次新建目录先持久化 `Intent`，再执行一次性写动作，结果只能转为 `Confirmed` 或 `OutcomeUnknown`。
7. 点击最终转存前持久化 durable `Submitting` 边界，并为该 DOM mutation 消费独立的一次性 permit。点击后保存官方请求标识或 source→destination exact-ID 映射。
8. 只有新增对象与 source exact set 一一对应且排除预先存在的同名对象后，任务才记为转存成功。点击后崩溃、超时或结果不完整统一进入 `ResultPending`，恢复只能读取目标目录和官方结果，禁止再次点击转存。
9. 若启用自动分享，直接把本次确认的 destination exact set 交给分享流程；否则提示转存完成。

## 8. 分享流程

- 分享对象必须来自转存结果中的 destination exact set：源为文件夹则分享文件夹，源为 APK 等单文件则分享对应文件；多个顶层对象作为同一个分享集合。
- 分享流程在同一账号浏览器中打开网盘目录、选中精确对象、创建分享链接与提取码。
- 分享提交前保存 exact resource set、分享设置、现有分享 ID 基线、generation token 和 durable `Submitting` 边界；点击创建分享需要独立 permit。结果不确定时进入 `ResultPending`，恢复只读检查新增分享，禁止重复创建。
- helper 只返回有类型的官方分享 receipt。分享结果仍由现有 C# 导出模块按用户选择的路径写入，并继续遵守原始列保留、多账号动态列、公式注入防护和不覆盖旧文件规则。
- 单独使用“分享”工作区时，用户可以选择账号和网盘中的对象后直接运行同一分享流程。
- 自动分享失败时只重试分享，不重新执行已确认成功的转存。

## 9. 浏览器生命周期与人工接管

- 正常批量执行时复用浏览器，不为每条资源重复启动。
- 页面加载、脚本执行或元素等待失败时，浏览器不立即消失；保留窗口并在软件中显示当前阶段和固定错误代号。
- 验证码或登录过期时暂停该账号，不占用其他账号的任务；用户处理后点击继续。
- 用户主动关闭浏览器时，当前操作进入“等待人工处理”或安全失败状态，不推断为成功。
- 程序退出时只关闭自己启动的自动化浏览器，不关闭用户的其他浏览器窗口。
- 用户在可见窗口中导航、切换标签或更换百度账号后，下一动作必须重新核验受控 Target、官方 HTTPS 主机与 route、页面阶段、稳定 UID、exact set 和 generation；任一项缺失或变化都必须零写并暂停。

## 10. 安全与数据边界

- 本地进程协议只接受固定动作类型、操作 ID、账号 ID、代次、ExecutionEngineVersion 和经过验证的路径；拒绝自由脚本和未知字段。
- 日志与错误结果不保存 Cookie、提取码、完整 URL、网页正文或账号 UID。
- 浏览器可执行文件、资料目录和导出目录均使用规范化绝对路径并限制在允许范围内。
- 远程调试端口仅本机可访问，退出后关闭；不得暴露到局域网或公网。
- 所有 DOM mutation 和远端写动作（填写并提交提取码、选择项目、打开目标选择器、进入目录、新建/确认目录、最终转存、创建分享）都继续受现有页面证据、操作代次和相应一次性 permit 约束。

## 11. 执行引擎固定与回退

- 数据库为每个 attempt 持久化 `ExecutionEngineVersion`，例如 `WebView2-v1` 或 `ManagedChromium-v1`。
- 数据库迁移为所有既有 attempt 和非终态 operation 回填非空 `WebView2-v1`；新字段完成回填和约束验证后才设为 `NOT NULL`。
- operation 和 attempt 都持久化并快照 `ExecutionEngineVersion + BrowserFamily + ProfileId`。一个逻辑操作从首次可能产生远端副作用开始到终态始终使用同一组合。
- 回退设置只影响尚未开始的新操作。已产生 source evidence、目录 mutation、基线、`Submitting` 或 `ResultPending` 的操作不得切换执行器。
- 重试生成新代次时，只有上一代已被证明 `DefinitelyNotSubmitted`，且没有目录 mutation、分享 mutation 或任何远端副作用，才允许使用当前默认引擎；否则新代次继承该逻辑操作原有的引擎、浏览器家族和 ProfileId。
- 升级时，旧在途操作继续由旧引擎完成，或安全暂停等待人工处理；不得由新引擎重新提交。
- 删除 WebView2 执行层前，必须确认没有旧引擎在途状态，并通过升级、回滚、崩溃恢复和重复写防护测试。

## 12. 保持不变的业务契约

- 现有导入、草稿修改、去重、删除/恢复、账号分配、任务数量/成功数量分配和批次状态接口保持不变。
- `WebAutomationAttemptRecord`、转存 source evidence、目标基线、目录 mutation、提交证据、官方结果映射和 `ResultPending` 只读恢复语义保持不变，仅更换证据采集与动作执行实现。
- 支持一个链接的单文件、单文件夹或多个顶层对象 exact set；一个导入行始终生成一个资源任务。
- 支持只转存、转存后自动分享、独立分享、多账号复制和多账号分流。
- 分享失败不重做已成功转存；导出失败不重做已成功分享。
- 最终 Excel/结果文件继续由现有 C# 导出模块生成。

## 13. 迁移顺序

1. 增加浏览器发现、手工选择、路径保存和专用资料目录管理。
2. 建立本地浏览器进程协议、启动/连接/关闭和健康检查。
3. 增加 `ManagedBrowserSessionReference`、数据库前向迁移、账号重新登录/UID 绑定、账号删除和 Profile 隔离。
4. 从现有分享源码中抽取最小页面适配逻辑，制作自包含、受限 IPC 的 helper。
5. 先实现只读页面识别，再实现分享适配器，并验证提交前基线、`Submitting` 和 `ResultPending` 恢复。
6. 增加分享链接识别、目标目录与转存适配器，逐个迁移目录 mutation 和最终转存写动作。
7. 按 `ExecutionEngineVersion` 把新适配器接入现有调度器；WebView2 只处理已固定为旧引擎的在途操作。
8. 完成真实单条转存、单条分享、转存后自动分享、崩溃恢复和升级/回滚验收后，再删除 WebView2 执行层。

## 14. 测试与验收

- 浏览器路径：Chrome、Edge、已保存路径、固定位置、路径失效、快速检查超时、手工选择、取消选择、被替换或同名伪造的 exe。
- 会话契约：legacy context 只能读取旧 Cookie store；managed context 无法访问旧 Cookie store；容量、目录、分享检查在浏览器未启动、未登录和 UID 不匹配时返回对应有类型结果。
- 资料目录：单账号复用、多账号隔离、Chrome/Edge 分离、进程占用、重解析点、权限、损坏隔离、异常退出后恢复、账号删除。
- 进程与端点：随机端口、端口抢占、错误 PID、未知监听者、旧进程、错误 BrowserId/TargetId、Job Object 退出和浏览器更新。
- 本地协议：启动前拒绝 helper 篡改/缺失/旧版本；拒绝未知动作、错误账号、错误代次、错误执行引擎、任意脚本、过大消息、乱序/迟到/重复 CorrelationId、伪造响应、抢连、握手超时和 helper 崩溃。
- 页面安全：非百度页面、非 HTTPS route、用户切换标签、账号 UID 变化、trusted root 缺失、页面 generation 变化时全部零写。
- 转存：文件夹、单文件、多顶层 exact set、提取码、目标目录逐段创建、预先存在同名对象、验证码、登录过期、用户关闭浏览器，以及每个提交边界前后崩溃。
- 分享：文件夹、APK 等单文件、多对象集合、已有分享基线、自动分享关闭/开启、分享失败不重转存、结果导出路径不可写、导出失败不重分享。
- 迁移：旧字段回填、`NOT NULL` 约束、旧账号重新登录、旧引擎在途操作、新引擎新操作、新代次继承条件、升级、回滚、禁止跨引擎恢复。
- 回归：导入、账号分配、批次状态、失败重试、数据库恢复和结果导出保持原行为。

现场验收按以下顺序进行，每次只操作一条可丢弃测试资源：

1. 启动本地浏览器并登录账号。
2. 只读打开分享链接并识别对象。
3. 转存到测试目录并核对网盘结果。
4. 对同一对象创建分享并核对导出结果。
5. 验证失败重试不会重复转存或分享。
