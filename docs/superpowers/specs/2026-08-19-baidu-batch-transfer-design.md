# 百度网盘批量转存客户端设计规格

日期：2026-08-19  
状态：待用户最终审阅

## 1. 产品目标

开发一款面向 Windows 10/11 64 位系统的本地桌面软件，帮助用户把大量百度网盘分享链接批量转存到用户自己的百度网盘账号。

第一版只支持百度网盘，不支持跨网盘转存。软件不设置硬编码的链接数量上限；20 万行只作为大批量压力测试基准，不代表产品上限或最低使用规模。系统需要支持多账号、两种多账号转存模式、配额分配、断点续跑、错误恢复和结果导出。

软件第一阶段不包含注册、会员、支付、激活码或云端管理服务。所有网盘登录态、任务数据和日志均保存在用户本机。

## 2. 约束与风险边界

- 软件采用用户授权的百度网页登录态，自动完成与用户手工转存相同目的的操作。
- 软件不提供绕过验证码、账号风控、平台频率限制或会员限制的能力。
- 遇到验证码或要求重新登录时，软件暂停对应账号并要求用户手工处理。
- 百度网页接口和页面可能变化。所有百度相关调用必须封装在可替换的适配层中，便于独立更新。
- 软件无法保证每条导入链接都成功。链接失效、提取码错误、容量不足、风控和百度服务异常均可能导致失败。
- 用户必须确保待转存内容及其使用方式合法，并遵守百度网盘的服务规则。

## 3. 技术方案

### 3.1 技术栈

- .NET 8
- WPF
- MVVM
- WebView2：打开百度官方登录页并完成扫码登录
- `HttpClient`：在授权登录态下执行必要的网页请求
- SQLite：持久化账号、批次、任务项、规则和日志
- Windows DPAPI：加密本机保存的敏感会话数据
- Excel 读写组件：生成模板、流式读取导入文件、导出结果

### 3.2 主要模块

1. **桌面界面层**：概览、账号池、资源导入、任务创建、任务中心和设置。
2. **登录会话模块**：扫码登录、手动 Cookie 导入、会话验证、过期检测和本机加密存储。
3. **链接解析模块**：从文本或 Excel 中提取分享链接、提取码和可选任务字段。
4. **百度适配器**：登录检查、容量读取、目录读取、链接预检、创建目录、执行转存和结果确认。
5. **账号规则引擎**：账号筛选、双模式展开、目录绑定、容量判断、轮询、任务配额和成功配额分配。
6. **任务引擎**：低并发执行、暂停恢复、冷却、有限重试、断点续跑和人工介入。
7. **数据存储模块**：SQLite 事务、批量写入、查询分页和状态恢复。
8. **Excel 模块**：模板生成、流式导入、字段映射和结果导出。
9. **日志模块**：结构化运行日志、错误分类和敏感信息脱敏。

### 3.3 构建与交付

- 第一版生成 Windows 10/11 x64 的 .NET 8 自包含安装包，目标电脑不要求预装 .NET Runtime。
- 安装程序检测 WebView2 Runtime；缺失时提供微软官方安装入口，不能静默下载未知来源组件。
- 开发验证阶段可以使用未签名构建；对外公开分发前必须使用可信代码签名，减少 Windows SmartScreen 警告。
- 所有 NuGet 和原生依赖在引入前确认许可证允许商业分发，并随安装包提供第三方许可证清单。
- 自动更新、会员和授权服务器仍不在第一版范围内；版本升级通过新的安装包完成，数据库迁移不得丢失任务。

## 4. 功能范围

### 4.1 账号池

- 支持添加多个百度网盘账号。
- 默认使用 WebView2 打开百度官方页面扫码登录。
- 支持手动导入 Cookie 作为备用方式。
- 显示账号昵称、登录状态、剩余容量、今日任务量、每日任务上限和启用状态。
- 登录失效、容量读取失败或被用户停用的账号不可参与新任务分配。
- Cookie 和其他敏感会话数据使用 DPAPI 加密，不保存百度密码。
- 每个账号使用独立的 WebView2 用户数据目录和浏览器 Profile，登录第二个账号不得覆盖第一个账号的登录态。
- 登录成功后读取百度稳定用户标识 `BaiduUserId`，在本地建立唯一约束；同一百度账号不能以不同 Cookie 或登录方式重复添加。
- WebView2 Profile、导出的 Cookie 会话和账号记录必须绑定同一个账号 ID。移除账号时同时清除该账号的浏览器 Profile 和加密会话。

### 4.2 文本导入

- 用户可以粘贴包含多个百度分享链接的整段文案。
- 自动提取链接和常见四位提取码。
- 规范化链接并去除完全重复项。
- 无法识别或格式异常的记录保留在异常列表中，供用户修正或排除。
- 未提供提取码不直接视为异常。公开分享或无需提取码的链接可以继续；只有百度在预检或执行时明确要求提取码，任务才标记为“缺少提取码”。文本与 Excel 使用相同规则。

### 4.3 Excel 导入

- 软件提供 Excel 模板。
- 支持字段：分享链接、提取码、目标目录、创建目录名称、指定账号和备注。
- 只有分享链接为必填；其他字段均可由任务创建页的全局设置补齐。
- 导入采用流式解析和批量写入，不能一次性把 20 万行全部呈现在内存或普通 WPF 表格中。
- 导入完成后显示有效、重复、异常和总记录数。

导入数据先进入草稿区，不直接进入可执行队列：

1. 创建 `ImportSession`，记录来源、解析进度和统计。
2. 每一行写入 `StagedImportRows`，状态为待处理、格式错误、重复、排除或就绪。
3. 用户可以通过分页视图修正提取码、目录、账号映射和备注，也可以排除记录。
4. 可选的批量预检结果持久化到草稿行。
5. 只有用户完成模式、账号配额或成功目标与最终确认后，才在数据库事务中创建 `BatchJob`、`ResourceItems`，并按模式预生成或延迟生成 `TransferOperations`。
6. 未确认的草稿永远不会被任务调度器读取。已提交草稿标记为已创建任务，用户可以手工删除；应用可在明确提示后清理长期未使用的草稿。

“暂停等待补充”不会重新打开已经提交的草稿。用户通过“追加候补资源”创建新的 `ImportSession` 并关联现有批次；新资源完成解析、去重和确认后，以事务方式追加为 `ResourceItems`。去重范围同时覆盖原批次已有资源和本次追加草稿。

- 每个批次维护单调递增的 `CandidateSequence`。首次导入按源行顺序编号；追加资源从当前最大编号之后继续，保证旧候选始终排在新候选之前。
- 追加资源继承批次模式、配额依据、资源不足策略、同名策略和每账号默认目录；Excel 行仍可提供允许的资源级目录和外层目录覆盖。
- 追加确认页显示原成功目标、当前已满足、进行中占位、新增候选、重新计算后的可达目标和未使用专属候选。
- `AwaitingCandidates` 批次在追加提交后进入 `PausedReady`；用户明确点击继续才恢复调度。
- `CompletedWithShortfall` 批次允许用户显式“重新打开并追加”。重新打开保留原成功目标和既有结果，重新激活仍可使用的未用候选，再追加新候选；不得重做已经满足的资源—账号操作。

重复与冲突判定：

- 解析器从百度分享 URL 提取稳定分享标识，形成 `NormalizedShareId`；跟踪参数、域名大小写、尾部标点和等价 URL 形式不影响身份。
- 分流模式下，同一 `NormalizedShareId` 在一个批次中只能作为一条源资源。完全相同的重复行自动折叠；提取码、目标目录、外层目录或指定账号不同时标记为冲突，由用户选择保留哪一条或切换为复制模式。
- 复制模式下，源资源仍只保留一条；确认批次时再按选中账号展开为多个转存操作，因此“同一链接进入不同账号”不是导入重复。
- 同一资源、同一账号、同一规范化目标目录和同一外层目录策略只允许存在一个未取消或已成功的转存操作。
- 草稿备注复制到源资源，并包含在结果导出中；备注不参与重复身份计算。

### 4.4 多账号转存模式

每个批次只能选择一种模式。需要混合行为时创建两个批次，避免配额、状态和结果含义混乱。

#### 多账号复制

- 每条资源保存到本批次选中的全部账号。
- 原始资源数与实际转存操作数分别统计；所有资源都复制到全部账号时，操作数等于资源数乘以账号数。
- 每个账号拥有独立的目标目录、同名策略执行结果和操作状态。
- 某个账号出现登录、容量或目录问题，只暂停该账号的操作，不影响其他账号。
- 分享链接被确认全局失效或提取码错误后，该资源对尚未执行的其他账号操作直接标记为全局无效，不重复请求。
- 同一资源在不同账号下不是重复；同一资源、同一账号、同一规范化目标目录和同一外层目录策略才构成重复操作。

#### 多账号分流

- 每条资源最终只保存到一个账号。
- 支持按任务数量分配，或按实际成功数量补足。
- 支持唯一账号、平均分配、固定数量/比例和按账号剩余容量比例分配任务数量。
- “按剩余容量”只按账号可用容量比例计算链接数量；未获取资源大小时不能保证最终空间占用完全均衡，界面必须提示这一点。

界面始终同时显示“原始资源数”和“实际转存操作数”。复制模式按账号展开操作；分流模式每条资源最多产生一个最终成功操作。

### 4.5 导入后的账号选择

- 只有一个有效账号时，该账号自动成为默认账号，并显示确认信息；复制与分流模式此时结果相同。
- 有两个及以上有效账号时，先选择“多账号复制”或“多账号分流”。
- 复制模式下，用户多选本批次参与账号，全部包含资源默认保存到所有选中账号。
- 分流模式下，用户可以选择唯一账号、平均分配、固定数量/比例分配或按剩余容量比例分配任务数量。
- Excel 中的账号列为空时，使用本次弹窗中的账号或账号池规则。
- Excel 账号名称可匹配时默认保留；无法匹配时要求用户映射到当前已登录账号。
- 用户可以选择保留 Excel 逐行指定，或用本次选择覆盖全部记录。
- 任务预览支持修改单条任务的账号，但只通过分页或虚拟化视图加载可见记录。
- Excel 的逐行指定账号只适用于分流模式。复制模式使用批次级账号集合；若表格包含逐行账号，用户必须选择忽略该列或改用分流模式，第一版不支持复制模式下逐行选择账号子集。

分流模式下，逐行指定账号与配额依据的关系如下：

- 按任务数量时，逐行指定账号和目录绑定账号先被解析，并计入对应账号的目标任务数量，而不是额外叠加。若锁定数量超过目标任务数量，用户不能继续。
- 按成功数量时，逐行指定账号和目录绑定账号形成账号专属候选，并不预先计为成功；界面显示专属候选数、公共候选数和成功目标。
- 计算基数是最终确认时所有“包含且就绪”的草稿行；已排除、重复、格式错误和批量预检不通过的行不参与。
- 配额和成功目标只针对本批次明确勾选的参与账号，不针对账号池中的所有启用账号。
- 按任务数量时，全部参与账号的目标任务数量总和必须等于就绪资源数；按成功数量时遵循第 4.6 节的候补池和资源不足规则。

### 4.6 账号配额与成功目标确认

任务创建采用自适应向导：导入数据、可选批量预检、选择目录、分配账号、确认任务。未选择批量预检时，该步骤显示为已跳过。配额确认始终发生在预检筛选和目录规则解析之后。

分流模式的账号分配页展示：

- 参与分配的账号及其状态和剩余容量。
- 每个账号的分配数量与占比。
- 导入总数、已分配数和未分配数。
- 平均分配、固定数量、固定比例和按剩余容量分配快捷方式。
- 是否采用加权交错绑定。

按任务数量分配时，所有本批参与账号的目标配额之和必须等于最终包含的就绪资源总数。逐行指定和目录绑定产生的锁定数量包含在目标配额中，剩余未锁定资源才使用加权算法补足各账号配额。

例如 20 万条链接可配置为：

- 账号 A：50,000 条
- 账号 B：100,000 条
- 账号 C：50,000 条

默认使用加权交错方式绑定任务，顺序近似为 `A, B, B, C` 循环，最终严格满足 `1:2:1` 的任务数量。

分流模式支持两种配额依据：

- **按任务数量**：资源一旦分配给账号就占用配额；资源失效或执行失败不会自动补位。成功数、失败数和未执行数分别统计。
- **按成功数量补足（默认）**：失效资源不占成功目标；调度器继续从尚未分配的候选资源池选择资源，直到账号达到成功目标或候选资源耗尽。

按成功数量补足时，用户还要选择候选资源不足策略：

- **按比例缩减（默认）**：保持各账号目标比例。批量预检已经知道有效数不足时，在执行前计算新目标并要求确认；运行中才发现不足时，使用加权公平调度使实际成功数尽量保持目标比例，候选池耗尽后记录原目标、有效目标和缺口。
- **账号优先级**：按用户排列的账号顺序先满足前面的账号，短缺由后面的账号承担。
- **暂停等待补充**：保持原成功目标，候选池耗尽时暂停；用户向同一草稿/批次补充新资源后继续。

成功目标总和可以小于包含资源数，多出的资源构成候补池；若成功目标总和等于包含资源数，则任一失效资源都可能造成目标缺口。除“暂停等待补充”外，创建时不允许成功目标总和大于当前包含资源数。

Excel 逐行指定账号在成功配额模式下表示该资源只能用于对应账号，属于账号专属候选资源，并不在任务创建时直接计为成功。调度器优先使用账号专属候选，再使用未指定账号的公共候选。账号已经达到成功目标后，未使用的专属候选标记为“候补未使用”，不得自动转给其他账号；确认页必须显示各账号专属候选数和可能造成的目标缺口。

默认使用加权公平调度，不要求先完成账号 A 才启动账号 B。调度器按目标比例交错选择账号；某条资源被确认全局失效时不增加任何账号的成功数，也不会再交给其他账号尝试。账号特定的临时失败保持原账号并按错误策略处理。

“成功目标”由“新转存成功”和“目标目录已存在且确认满足”共同构成，界面分别统计二者；预检、失败、取消和结果待确认均不计入成功目标。

为防止超过成功目标，每个账号使用以下恒等式：

`可领取席位 = 有效成功目标 - 已满足数 - 进行中占位数`

- 调度器只有在可领取席位大于零时才能为该账号保留新候选。
- 操作进入账号保留、检测、准备提交、提交中或结果待确认后持续占用一个席位。
- 新转存成功或已存在满足时，占位原子转换为已满足。
- 明确全局失效、确认未提交的终止失败或用户确认取消时释放占位。
- 结果待确认始终保留占位；在结果确认前不得创建替代操作。这样后续确认原操作成功时不会超过目标。

默认“按比例缩减”的确定性分配算法如下：

1. 使用原成功目标作为账号权重，初始化每个账号的已满足数和进行中占位数。
2. 在仍有可用候选和未满足目标时，选择 `(已满足数 + 进行中占位数) / 原成功目标` 最小的账号，即比例进度最落后的账号；相同比值按用户确认的账号顺序决定。
3. 对选中账号优先取该账号 `CandidateSequence` 最小的专属候选，没有专属候选时取序号最小的公共候选。
4. 专属候选不能被其他账号使用。账号已达到原目标后的专属剩余标记为候补未使用。
5. 已知有效候选不足时，用同一算法只按“专属候选数量和公共候选数量”模拟到候选耗尽，得到整数有效目标；因此舍入和尾数归属与真实调度一致。
6. 运行中发现失效时释放占位并继续同一算法。只有候选池耗尽、没有进行中占位和结果待确认后，才确定最终有效目标或缺口。

参与成功配额调度的账号目标必须大于零；目标为零的账号从本批参与集合移除，避免无意义分配和除零。

候选选择由单一调度协调器串行完成，并在事务中写入单调递增的 `AllocationOrdinal` 后才交给最多两个执行工作器。并发只发生在网络执行阶段，不允许多个工作器自行竞争候选，因此相同输入、账号顺序和状态变化能得到可重放的分配顺序。

账号优先级策略改为按用户顺序选择第一个仍有可领取席位且有可用专属或公共候选的账号；专属候选同样不可跨账号。任何策略下，专属候选的剩余数量都不能被当作其他账号的可用资源。

复制模式不使用总和配额。确认页展示每个选中账号需要接收的资源数、总操作数和各自目标目录；每个账号的目标默认等于全部包含资源数。

创建任务前显示最终确认摘要，包括模式、资源数量、操作数量、账号配额或成功目标、资源不足策略、目标目录、创建目录策略、同名策略和预检模式。用户明确确认后才写入可执行队列。

### 4.7 目标目录与目录创建

- 支持为批次设置统一目标目录。
- 复制模式允许每个参与账号设置各自的默认目标目录；批次统一目录只是首次填充值。
- Excel 或任务预览可以为单条记录覆盖目标目录。
- 默认保持分享资源原有结构。
- 用户可以全局或逐条开启外层目录创建。
- 外层目录名称支持资源标题或自定义名称。
- 批次确认时，把资源级目标目录覆盖、规范化目录覆盖、外层目录名称和外层目录模式复制到 `ResourceItems`；提交草稿随后即使被清理，延迟操作仍可确定性生成。
- 每个参与账号的默认目录和规范化目录保存在 `AccountAllocations`。创建延迟操作时，以“资源级覆盖优先，否则账号默认目录”计算最终路径，并把最终值快照到 `TransferOperations`，后续账号默认设置变化不追溯修改已有操作。

### 4.8 同名处理

创建任务时由用户选择同名处理策略，任务启动后保持固定。可选策略为：

- 跳过并记录
- 自动重命名
- 尝试合并或覆盖（仅在百度当前能力明确支持时启用）

界面应解释每种策略的可能结果，不承诺百度不支持的覆盖语义。

### 4.9 链接检测

- 默认在每条任务执行前进行即时检测。
- 提供可选的批量预检功能。
- 预检状态包括：有效、失效、提取码错误、需要验证、暂时无法判断和格式错误。
- 用户可以只把预检有效的链接加入任务。
- 批量预检同样采用低并发和断点续跑，避免集中请求。
- 大批量导入默认仍使用执行前即时检测。批量预检是用户主动选择的耗时操作；确认页显示预估请求量，并提示单个预检账号可能成为瓶颈或触发人工验证。

批量预检发生在账号配额确认之前，流程为：导入与修正草稿、选择是否批量预检、确认预检账号、执行并保存预检结果、决定排除哪些无效行、再对剩余就绪行设置账号配额。

- 批量预检需要登录态时，用户从有效账号中选择一个预检账号；默认选择本批次第一个有效账号。
- 预检账号只用于检测，不会成为最终转存账号，也不消耗转存配额。
- 预检账号需要验证码或登录失效时暂停预检，用户处理后继续；软件不自动切换账号。
- 未执行批量预检时，配额基于所有用户保留的就绪行。每条任务在执行前使用其最终绑定账号即时检测。
- 批量预检后新增、编辑链接或提取码会使该行原预检结果失效，必须重新预检或按未预检状态进入队列。

### 4.10 任务中心

- 状态包括：等待、检测中、准备提交、提交中、成功、失败、暂停、等待人工验证、结果待确认和已取消。
- 默认每个账号同时执行一条任务，全局最多同时执行两条。
- 第一版允许用户降低并发，不允许高于安全上限。
- 每个状态变化立即持久化。软件退出、崩溃或电脑重启后可以继续未完成任务。
- 支持暂停批次、继续批次、暂停账号、单条重试、批量重试和取消尚未执行的任务。
- 取消任务不得删除历史结果和日志。
- 支持按批次、账号、状态和时间筛选，并导出 Excel。
- “已取消”只适用于尚未开始提交的任务项；正在提交或结果待确认的任务不能直接取消，必须先完成结果确认。
- 应用使用 Windows 单实例互斥锁。同一 Windows 用户不能同时启动两个调度器读取同一数据库；第二次启动只激活已有窗口。
- 第一版同一时间只允许一个活动批次。其他批次保持排队，用户可调整顺序或手工切换；切换前先安全暂停当前批次。
- 关闭主窗口时让用户选择“最小化到系统托盘继续运行”或“安全暂停并退出”，并可记住选择。安全退出停止领取新任务，等待正在提交的操作进入可恢复状态后退出。
- 断网时停止领取新任务并显示离线状态；网络恢复后由用户确认继续。Windows 休眠与唤醒后重新验证网络和账号会话，再恢复调度。

每日上限以用户当前 Windows 时区的本地自然日计算，并在本地午夜进入新日期时重置。应用同时保存日期键和计数，重启后继续使用。达到上限后，该账号的未执行任务保持暂停直到下一本地自然日；软件可以继续执行已绑定给其他正常账号的任务，但不会自动重分配受限账号的任务。用户可手工重新分配尚未执行的剩余任务。

`DailyExecutedCount` 在某个转存操作第一次持久化进入“提交中”时增加一次。相同操作的网络重试、结果确认和应用重启不重复增加；预检、格式错误和未提交取消不计数。用户界面同时显示“今日提交操作数”和“今日成功数”，避免把账号安全上限与成功统计混淆。

## 5. 账号分配规则

复制模式在批次确认时把每条包含资源展开到全部参与账号，形成确定的资源—账号操作集合；账号之间的状态相互独立。

分流模式按配额依据处理：

- **按任务数量**：先解析 Excel 或任务预览明确指定的账号，再解析目标目录绑定的固定账号；这些资源被锁定并计入对应账号目标数量。剩余资源按唯一账号、平均、固定数量/比例或容量比例生成目标数量，再按轮询或加权交错确定性绑定。创建后不动态漂移。
- **按成功数量补足**：逐行账号和目录绑定仍然优先，但未锁定资源保留在候选池。调度器以数据库事务原子保留下一条候选资源并为目标账号创建操作。操作只有在“新转存成功”或“已存在且满足”时才增加该账号的已满足数；全局失效资源释放该次机会，调度器继续选择候选资源。

“按剩余容量”是生成目标比例的一种方式，不是在其他配额之外追加的运行时规则。未获得资源大小时只代表按账号剩余容量比例分配资源条数。

账号在执行中失效时：

- 已经成功、失败或结果待确认的任务保持原账号。
- 按任务数量模式下，尚未执行的已绑定任务保持暂停状态；按成功数量模式下，尚未从候选池领取的资源保持未分配。
- 用户可以修复原账号后继续，也可以明确选择“重新分配剩余任务”。
- 重新分配会显示新的账号目标数量、变化量和受影响任务数，用户再次确认后才更新尚未执行的任务与 `AccountAllocations`。
- 软件在用户确认前不得擅自改变账号配额。

## 6. 执行流程

单个转存操作的正常流程为：

1. 读取已展开操作，或在成功配额模式下用同一数据库事务检查可领取席位、原子保留一条候选资源、创建目标账号操作并增加 `ReservedSlotCount`。
2. 确认目标账号仍可用。
3. 检查登录状态。
4. 解析并验证分享链接和提取码。
5. 确认目标目录。
6. 按需创建外层目录。
7. 生成本次操作指纹，并在发起网络请求前持久化“准备提交”状态。
8. 在同一数据库事务中将状态持久化为“提交中”，并在该操作首次提交时增加账号当日提交计数，然后发起转存。
9. 校验响应或目标目录结果。
10. 持久化最终状态、源资源的全局有效性、账号配额满足计数和脱敏日志。

任务必须使用数据库租约或等效机制防止同一任务被重复执行。应用异常退出后：

- 检测中或尚未进入“准备提交”的过期租约可以恢复为等待状态。
- 任何已经进入“准备提交”或“提交中”但没有最终结果的任务，一律恢复为“结果待确认”，不得自动重新提交。
- 恢复流程先根据账号、目标目录、预期目录或文件名称、操作指纹和时间窗口进行结果核对。能确定目标资源已经存在时记为成功；能确定请求未执行时才允许重新排队；无法确定时要求用户确认。
- 用户手工选择重试“结果待确认”的操作前，界面必须提示可能产生重复资源。

`AccountAllocations` 中的占位和满足计数是事务维护的缓存。应用启动恢复时根据 `TransferOperations.TargetSlotState` 重算并核对；不一致时以操作明细为准修复计数后才启动调度。

## 7. 错误处理

### 7.1 可自动重试

- 临时网络错误
- 明确未被服务器接受的请求超时
- 百度服务临时繁忙

采用有限退避和冷却，默认最多三次。若服务器返回明确的等待时间，应遵循该时间。

### 7.2 需要用户处理

- 验证码
- 登录失效
- Cookie 过期
- 百度要求重新确认账号

暂停对应账号，不自动处理验证码。其他正常账号可以继续执行。

### 7.3 不自动重试

- 链接失效
- 提取码错误
- 目标路径非法或不存在
- 账号容量不足
- 明确的权限错误

错误必须同时标记作用域：

- 分享链接明确失效、明确提取码错误属于资源全局错误。复制模式可停止该资源尚未执行的其他账号操作；分流模式不把该资源交给其他账号补试。
- 登录失效、验证码、目标目录、容量和账号权限属于账号或操作错误，不得据此把源资源标记为全局失效。
- 错误响应无法可靠判断作用域时按操作错误处理并进入人工确认，不传播到其他账号。
- 成功配额模式下，账号特定错误不会自动把已经提交过的资源重新分配给其他账号。只有用户确认原操作未生效后，才允许恢复候选或重新分配。

### 7.4 结果不确定

请求发出后超时，且无法确认服务器是否已经完成转存时，将任务标记为“结果待确认”。软件先查询目标目录；能够确认资源已存在时记为成功，否则等待用户选择再次确认或重试，不直接重复提交。

“准备提交”和“提交中”是持久化子状态，不是只存在内存中的进度文字。这样即使应用在请求发送边界崩溃，也不会因租约过期而自动重复执行。

## 9. 大数据量设计

- Excel 与文本导入采用流式解析。
- 每批次以数据库批量事务写入，避免逐行提交。
- 任务表按批次、状态、账号和序号建立必要索引。
- WPF 表格使用 UI 虚拟化与数据库分页，不实例化 20 万个行视图模型。
- 配额分配通过确定性算法分批写入，不构建巨大的内存列表。
- 复制模式展开操作前估算操作数量和本地数据库空间；可用磁盘不足时阻止创建并提示释放空间。软件不使用固定链接上限，但必须受实际磁盘空间和可恢复事务能力约束。
- 概览统计优先使用数据库聚合和缓存计数，不重复扫描全部任务。
- 导出采用流式写出，并显示进度和取消入口。
- 详细执行日志默认保留 30 天且最多占用 500 MB，先清理最旧的已完成批次明细；批次汇总和最终结果保留到用户删除批次。用户可以手工导出后清理。

在 4 核 CPU、8 GB 内存和 SSD 的基准 Windows 测试机上，20 万行标准 Excel 的目标为：

- 解析并持久化在 5 分钟内完成。
- 导入期间应用峰值工作集不超过 1 GB。
- 除文件选择等系统窗口外，主界面不出现持续 500 毫秒以上的无响应。
- 分页切换和常用筛选在已有索引命中的情况下 1 秒内返回首屏结果。
- 复制模式使用至少三个模拟账号时，操作展开、统计和分页同样不得一次性加载全部操作到 UI 内存。

这些指标用于验收和回归；真实速度仍取决于文件内容、磁盘和设备性能。

## 10. 安全与隐私

- WebView2 仅允许导航至百度官方登录和网盘所需域名；异常跳转应阻止并提示。
- 不同账号使用隔离的 WebView2 Profile。Profile 目录可能包含浏览器会话数据，必须放在当前用户应用数据目录、继承当前用户访问控制，并在移除账号时删除。
- 不在日志中记录完整 Cookie、请求签名、敏感请求头或完整个人标识。
- DPAPI 加密数据只能由当前 Windows 用户解密。
- 手动导入 Cookie 的界面明确提示敏感性，输入默认遮挡，保存前再次确认账号信息。
- 数据库和日志默认存放在当前用户应用数据目录，不需要管理员权限。
- 第一版 SQLite 任务数据库不宣称内容加密；它依赖 Windows 当前用户文件权限保护。可复用的登录会话仍单独使用 DPAPI 加密。
- Excel 导出把链接、备注和错误文本作为文本单元格写入；以 `=`, `+`, `-`, `@` 开头的非数值内容必须转义，防止电子表格公式注入。
- 提供“移除账号并清除本机会话”和“清除全部本地数据”功能；执行前明确确认。

## 12. 第一版验收标准

1. 能通过扫码或手动 Cookie 添加至少三个百度账号；账号 Profile 相互隔离，相同百度账号不能重复添加。
2. 能正确导入文本和 Excel，产品不设置硬编码链接上限，并在模拟数据下处理 20 万条记录而不冻结界面或耗尽内存。
3. 导入数据先进入草稿区，未最终确认的记录不会进入执行队列；异常行、重复项、修正和预检结果可恢复。
4. 复制模式能把每条资源展开到所有选中账号；1,000 条资源与三个账号产生 3,000 个独立可恢复操作。
5. 按任务数量分流能以 50,000、100,000、50,000 的配额把 20 万条资源确定性绑定到三个账号，并正确扣除逐行指定和目录绑定产生的锁定数量。
6. 按成功数量补足时，失效资源不占成功目标；能按比例缩减、账号优先级或等待补充三种策略结束或暂停资源不足批次。
7. 配额不等于最终包含的就绪资源数，或任一账号锁定数量超过目标配额时，任务数量模式无法继续创建任务。
8. 批量预检发生在配额确认前，预检排除记录后以剩余就绪数量重新计算配额或成功目标。
9. 支持统一目录、单条覆盖目录和可选外层目录。
10. 支持创建任务时选择同名策略。
11. 支持即时检测和批量预检两种模式。
12. 支持单实例、单活动批次、暂停、继续、取消未提交操作、安全退出、应用重启后的断点续跑和失败结果导出。
13. 在提交边界异常退出时，操作进入结果待确认状态且不会自动重复提交。
14. 每日账号上限按 Windows 本地自然日重置；同一操作重试不重复计数，并在重启后保持正确计数。
15. 验证码或登录失效只暂停对应账号，且不会被软件自动绕过。
16. Cookie 经 DPAPI 加密，日志不包含可复用的敏感会话信息；Excel 导出不会执行用户数据中的公式。
17. 数据库支持迁移前备份、WAL、损坏检测和日志轮转。
18. 百度适配器能够独立替换，不要求修改任务、存储和界面核心模块。
19. 20 万行模拟导入满足第 9 节规定的基准性能指标。
20. 已提交草稿被清理后，成功配额模式仍能根据源资源快照和账号目录设置创建相同的延迟操作。
21. 进行中和结果待确认操作占用成功目标席位，任何执行与崩溃恢复顺序都不会让账号已满足数超过有效目标。
22. 对相同专属/公共候选数量、账号顺序和目标比例，比例缩减算法每次产生相同的整数有效目标和候选选择顺序。
23. 追加候选接续原候选序号、继承批次设置，并只能在用户确认后把等待候选或缺口完成批次恢复为可执行状态。

## 13. 实施前技术验证

正式铺开界面和任务系统前，先完成一个受控的小规模百度适配器验证：

1. 验证 WebView2 扫码登录和会话读取在 Windows 10/11 上可行。
2. 识别运行所需的百度官方域名清单，并验证导航限制不会破坏登录。
3. 使用用户自有的合法测试链接验证分享信息读取、提取码处理、目录选择和整条链接转存。
4. 确认百度当前对同名资源、目录合并和响应错误码的真实行为。
5. 验证登录失效、验证码和频率限制能够被识别并转为暂停状态。
6. 将观察到的请求和响应语义收敛到 `IBaiduNetdiskAdapter`，不得让网页字段或接口细节泄漏到 UI、任务或数据库层。

如果扫码会话无法安全传递、整条链接转存不可稳定确认，或必要行为只能依赖规避平台安全措施，则停止正式实现并回到设计评估，不继续扩大开发范围。

## 14. 明确不在第一版范围内

- 其他网盘
- 跨网盘下载后再上传
- 分享链接内的部分文件选择
- 同一个复制批次内为每条链接单独选择不同的账号子集
- 自动处理验证码
- 绕过百度风控、限速或会员限制
- 云端同步账号凭证或任务数据
- 注册、会员、支付、激活码和自动更新服务
- macOS、Linux、移动端和网页版
