# 百度网盘批量转存客户端设计规格

日期：2026-08-19  
状态：待用户最终审阅

## 1. 产品目标

开发一款面向 Windows 10/11 64 位系统的本地桌面软件，帮助用户把大量百度网盘分享链接批量转存到用户自己的百度网盘账号。

第一版只支持百度网盘，不支持跨网盘转存。单批任务需要可靠处理 20 万条及以上链接，并支持多账号、配额分配、断点续跑、错误恢复和结果导出。

软件第一阶段不包含注册、会员、支付、激活码或云端管理服务。所有网盘登录态、任务数据和日志均保存在用户本机。

## 2. 约束与风险边界

- 软件采用用户授权的百度网页登录态，自动完成与用户手工转存相同目的的操作。
- 软件不提供绕过验证码、账号风控、平台频率限制或会员限制的能力。
- 遇到验证码或要求重新登录时，软件暂停对应账号并要求用户手工处理。
- 百度网页接口和页面可能变化。所有百度相关调用必须封装在可替换的适配层中，便于独立更新。
- 软件无法保证每条导入链接都成功。链接失效、提取码错误、容量不足、风控和百度服务异常均可能导致失败。
- 用户必须确保待转存内容及其使用方式合法，并遵守百度网盘的服务规则。

## 3. 技术方案

### 3.1 技术栈

- .NET 8
- WPF
- MVVM
- WebView2：打开百度官方登录页并完成扫码登录
- `HttpClient`：在授权登录态下执行必要的网页请求
- SQLite：持久化账号、批次、任务项、规则和日志
- Windows DPAPI：加密本机保存的敏感会话数据
- Excel 读写组件：生成模板、流式读取导入文件、导出结果

### 3.2 主要模块

1. **桌面界面层**：概览、账号池、资源导入、任务创建、任务中心和设置。
2. **登录会话模块**：扫码登录、手动 Cookie 导入、会话验证、过期检测和本机加密存储。
3. **链接解析模块**：从文本或 Excel 中提取分享链接、提取码和可选任务字段。
4. **百度适配器**：登录检查、容量读取、目录读取、链接预检、创建目录、执行转存和结果确认。
5. **账号规则引擎**：账号筛选、目录绑定、容量判断、轮询和配额分配。
6. **任务引擎**：低并发执行、暂停恢复、冷却、有限重试、断点续跑和人工介入。
7. **数据存储模块**：SQLite 事务、批量写入、查询分页和状态恢复。
8. **Excel 模块**：模板生成、流式导入、字段映射和结果导出。
9. **日志模块**：结构化运行日志、错误分类和敏感信息脱敏。

## 4. 功能范围

### 4.1 账号池

- 支持添加多个百度网盘账号。
- 默认使用 WebView2 打开百度官方页面扫码登录。
- 支持手动导入 Cookie 作为备用方式。
- 显示账号昵称、登录状态、剩余容量、今日任务量、每日任务上限和启用状态。
- 登录失效、容量读取失败或被用户停用的账号不可参与新任务分配。
- Cookie 和其他敏感会话数据使用 DPAPI 加密，不保存百度密码。

### 4.2 文本导入

- 用户可以粘贴包含多个百度分享链接的整段文案。
- 自动提取链接和常见四位提取码。
- 规范化链接并去除完全重复项。
- 无法识别或格式异常的记录保留在异常列表中，供用户修正或排除。
- 未提供提取码不直接视为异常。公开分享或无需提取码的链接可以继续；只有百度在预检或执行时明确要求提取码，任务才标记为“缺少提取码”。文本与 Excel 使用相同规则。

### 4.3 Excel 导入

- 软件提供 Excel 模板。
- 支持字段：分享链接、提取码、目标目录、创建目录名称、指定账号和备注。
- 只有分享链接为必填；其他字段均可由任务创建页的全局设置补齐。
- 导入采用流式解析和批量写入，不能一次性把 20 万行全部呈现在内存或普通 WPF 表格中。
- 导入完成后显示有效、重复、异常和总记录数。

导入数据先进入草稿区，不直接进入可执行队列：

1. 创建 `ImportSession`，记录来源、解析进度和统计。
2. 每一行写入 `StagedImportRows`，状态为待处理、格式错误、重复、排除或就绪。
3. 用户可以通过分页视图修正提取码、目录、账号映射和备注，也可以排除记录。
4. 可选的批量预检结果持久化到草稿行。
5. 只有用户完成账号配额与最终确认后，才在一个数据库事务中创建 `BatchJob` 和对应的 `TransferItems`。
6. 未确认的草稿永远不会被任务调度器读取。已提交草稿标记为已创建任务，用户可以手工删除；应用可在明确提示后清理长期未使用的草稿。

### 4.4 导入后的账号选择

- 只有一个有效账号时，该账号自动成为默认账号，并显示确认信息。
- 有两个及以上有效账号时，弹出账号分配步骤。
- 用户可以选择唯一账号、平均分配、固定数量/比例分配或按剩余容量分配。
- Excel 中的账号列为空时，使用本次弹窗中的账号或账号池规则。
- Excel 账号名称可匹配时默认保留；无法匹配时要求用户映射到当前已登录账号。
- 用户可以选择保留 Excel 逐行指定，或用本次选择覆盖全部记录。
- 任务预览支持修改单条任务的账号，但只通过分页或虚拟化视图加载可见记录。

逐行指定账号与批次配额的关系如下：

- 逐行指定账号和目录绑定账号先被解析，并计入对应账号的目标配额，而不是额外叠加。
- 配额的分母是最终确认时所有“包含且就绪”的草稿行；已排除、重复、格式错误和批量预检不通过的行不参与配额。
- 配额只针对本批次明确勾选的参与账号，不针对账号池中的所有启用账号。
- 每个账号同时显示“已被逐行/目录规则锁定的数量”和“仍需自动分配的数量”。
- 若某账号已经锁定的数量大于用户填写的目标配额，或全部参与账号的目标配额总和不等于就绪行总数，用户不能继续。

### 4.5 账号配额确认

任务创建采用自适应向导：导入数据、可选批量预检、选择目录、分配账号、确认任务。未选择批量预检时，该步骤显示为已跳过。配额确认始终发生在预检筛选和目录规则解析之后。

账号分配页展示：

- 参与分配的账号及其状态和剩余容量。
- 每个账号的分配数量与占比。
- 导入总数、已分配数和未分配数。
- 平均分配、固定数量、固定比例和按剩余容量分配快捷方式。
- 是否采用加权交错绑定。

只有所有本批参与账号的目标配额之和等于最终包含的就绪任务总数时，用户才能继续。逐行指定和目录绑定产生的锁定数量包含在目标配额中，剩余未锁定记录才使用加权算法补足各账号配额。

例如 20 万条链接可配置为：

- 账号 A：50,000 条
- 账号 B：100,000 条
- 账号 C：50,000 条

默认使用加权交错方式绑定任务，顺序近似为 `A, B, B, C` 循环，最终严格满足 `1:2:1` 的任务数量。

“分配数量”表示绑定到该账号的任务项数量，不保证相同数量最终成功。成功数、失败数和未执行数分别统计。

创建任务前显示最终确认摘要，包括导入数量、账号配额、目标目录、创建目录策略、同名策略和预检模式。用户明确确认后才写入可执行队列。

### 4.6 目标目录与目录创建

- 支持为批次设置统一目标目录。
- Excel 或任务预览可以为单条记录覆盖目标目录。
- 默认保持分享资源原有结构。
- 用户可以全局或逐条开启外层目录创建。
- 外层目录名称支持资源标题或自定义名称。

### 4.7 同名处理

创建任务时由用户选择同名处理策略，任务启动后保持固定。可选策略为：

- 跳过并记录
- 自动重命名
- 尝试合并或覆盖（仅在百度当前能力明确支持时启用）

界面应解释每种策略的可能结果，不承诺百度不支持的覆盖语义。

### 4.8 链接检测

- 默认在每条任务执行前进行即时检测。
- 提供可选的批量预检功能。
- 预检状态包括：有效、失效、提取码错误、需要验证、暂时无法判断和格式错误。
- 用户可以只把预检有效的链接加入任务。
- 批量预检同样采用低并发和断点续跑，避免集中请求。

批量预检发生在账号配额确认之前，流程为：导入与修正草稿、选择是否批量预检、确认预检账号、执行并保存预检结果、决定排除哪些无效行、再对剩余就绪行设置账号配额。

- 批量预检需要登录态时，用户从有效账号中选择一个预检账号；默认选择本批次第一个有效账号。
- 预检账号只用于检测，不会成为最终转存账号，也不消耗转存配额。
- 预检账号需要验证码或登录失效时暂停预检，用户处理后继续；软件不自动切换账号。
- 未执行批量预检时，配额基于所有用户保留的就绪行。每条任务在执行前使用其最终绑定账号即时检测。
- 批量预检后新增、编辑链接或提取码会使该行原预检结果失效，必须重新预检或按未预检状态进入队列。

### 4.9 任务中心

- 状态包括：等待、检测中、准备提交、提交中、成功、失败、暂停、等待人工验证、结果待确认和已取消。
- 默认每个账号同时执行一条任务，全局最多同时执行两条。
- 第一版允许用户降低并发，不允许高于安全上限。
- 每个状态变化立即持久化。软件退出、崩溃或电脑重启后可以继续未完成任务。
- 支持暂停批次、继续批次、暂停账号、单条重试、批量重试和取消尚未执行的任务。
- 取消任务不得删除历史结果和日志。
- 支持按批次、账号、状态和时间筛选，并导出 Excel。
- “已取消”只适用于尚未开始提交的任务项；正在提交或结果待确认的任务不能直接取消，必须先完成结果确认。

每日上限以用户当前 Windows 时区的本地自然日计算，并在本地午夜进入新日期时重置。应用同时保存日期键和计数，重启后继续使用。达到上限后，该账号的未执行任务保持暂停直到下一本地自然日；软件可以继续执行已绑定给其他正常账号的任务，但不会自动重分配受限账号的任务。用户可手工重新分配尚未执行的剩余任务。

## 5. 账号分配规则

任务创建时分两阶段决定账号：

1. 先解析 Excel 或任务预览明确指定的账号，再解析目标目录绑定的固定账号；这些任务被锁定并计入对应账号配额。
2. 对剩余未锁定任务，用户选择唯一账号、平均分配、固定数量/比例或按剩余容量生成目标配额。系统计算每个账号尚需补足的数量，再按轮询或加权交错顺序确定性绑定。

“按剩余容量”是生成目标配额的一种方式，不是在固定配额之外追加的运行时规则。所有模式最终都会得到每个参与账号的明确目标数量。任务在创建阶段就绑定账号，不在执行阶段动态漂移。

账号在执行中失效时：

- 已经成功、失败或结果待确认的任务保持原账号。
- 尚未执行的任务保持暂停状态。
- 用户可以修复原账号后继续，也可以明确选择“重新分配剩余任务”。
- 重新分配会显示新的账号目标数量、变化量和受影响任务数，用户再次确认后才更新尚未执行的任务与 `AccountAllocations`。
- 软件在用户确认前不得擅自改变账号配额。

## 6. 执行流程

单条任务的正常流程为：

1. 读取任务并锁定。
2. 确认目标账号仍可用。
3. 检查登录状态。
4. 解析并验证分享链接和提取码。
5. 确认目标目录。
6. 按需创建外层目录。
7. 生成本次操作指纹，并在发起网络请求前持久化“准备提交”状态。
8. 将状态持久化为“提交中”后发起转存。
9. 校验响应或目标目录结果。
10. 持久化最终状态和脱敏日志。

任务必须使用数据库租约或等效机制防止同一任务被重复执行。应用异常退出后：

- 检测中或尚未进入“准备提交”的过期租约可以恢复为等待状态。
- 任何已经进入“准备提交”或“提交中”但没有最终结果的任务，一律恢复为“结果待确认”，不得自动重新提交。
- 恢复流程先根据账号、目标目录、预期目录或文件名称、操作指纹和时间窗口进行结果核对。能确定目标资源已经存在时记为成功；能确定请求未执行时才允许重新排队；无法确定时要求用户确认。
- 用户手工选择重试“结果待确认”的任务前，界面必须提示可能产生重复资源。

## 7. 错误处理

### 7.1 可自动重试

- 临时网络错误
- 明确未被服务器接受的请求超时
- 百度服务临时繁忙

采用有限退避和冷却，默认最多三次。若服务器返回明确的等待时间，应遵循该时间。

### 7.2 需要用户处理

- 验证码
- 登录失效
- Cookie 过期
- 百度要求重新确认账号

暂停对应账号，不自动处理验证码。其他正常账号可以继续执行。

### 7.3 不自动重试

- 链接失效
- 提取码错误
- 目标路径非法或不存在
- 账号容量不足
- 明确的权限错误

### 7.4 结果不确定

请求发出后超时，且无法确认服务器是否已经完成转存时，将任务标记为“结果待确认”。软件先查询目标目录；能够确认资源已存在时记为成功，否则等待用户选择再次确认或重试，不直接重复提交。

“准备提交”和“提交中”是持久化子状态，不是只存在内存中的进度文字。这样即使应用在请求发送边界崩溃，也不会因租约过期而自动重复执行。

## 9. 大数据量设计

- Excel 与文本导入采用流式解析。
- 每批次以数据库批量事务写入，避免逐行提交。
- 任务表按批次、状态、账号和序号建立必要索引。
- WPF 表格使用 UI 虚拟化与数据库分页，不实例化 20 万个行视图模型。
- 配额分配通过确定性算法分批写入，不构建巨大的内存列表。
- 概览统计优先使用数据库聚合和缓存计数，不重复扫描全部任务。
- 导出采用流式写出，并显示进度和取消入口。

在 4 核 CPU、8 GB 内存和 SSD 的基准 Windows 测试机上，20 万行标准 Excel 的目标为：

- 解析并持久化在 5 分钟内完成。
- 导入期间应用峰值工作集不超过 1 GB。
- 除文件选择等系统窗口外，主界面不出现持续 500 毫秒以上的无响应。
- 分页切换和常用筛选在已有索引命中的情况下 1 秒内返回首屏结果。

这些指标用于验收和回归；真实速度仍取决于文件内容、磁盘和设备性能。

## 10. 安全与隐私

- WebView2 仅允许导航至百度官方登录和网盘所需域名；异常跳转应阻止并提示。
- 不在日志中记录完整 Cookie、请求签名、敏感请求头或完整个人标识。
- DPAPI 加密数据只能由当前 Windows 用户解密。
- 手动导入 Cookie 的界面明确提示敏感性，输入默认遮挡，保存前再次确认账号信息。
- 数据库和日志默认存放在当前用户应用数据目录，不需要管理员权限。
- 提供“移除账号并清除本机会话”和“清除全部本地数据”功能；执行前明确确认。

## 12. 第一版验收标准

1. 能通过扫码或手动 Cookie 添加至少三个百度账号。
2. 能正确导入文本和 Excel，并在模拟数据下处理 20 万条记录而不冻结界面或耗尽内存。
3. 导入数据先进入草稿区，未最终确认的记录不会进入执行队列；异常行、重复项、修正和预检结果可恢复。
4. 能以 50,000、100,000、50,000 的配额把 20 万条任务确定性绑定到三个账号，并正确扣除逐行指定和目录绑定产生的锁定数量。
5. 配额不等于最终包含的就绪任务数，或任一账号锁定数量超过目标配额时，无法继续创建任务。
6. 批量预检发生在配额确认前，预检排除记录后以剩余就绪数量重新计算配额。
7. 支持统一目录、单条覆盖目录和可选外层目录。
8. 支持创建任务时选择同名策略。
9. 支持即时检测和批量预检两种模式。
10. 支持暂停、继续、取消未提交任务、应用重启后的断点续跑和失败结果导出。
11. 在提交边界异常退出时，任务进入结果待确认状态且不会自动重复提交。
12. 每日账号上限按 Windows 本地自然日重置，并在重启后保持正确计数。
13. 验证码或登录失效只暂停对应账号，且不会被软件自动绕过。
14. Cookie 经 DPAPI 加密，日志不包含可复用的敏感会话信息。
15. 百度适配器能够独立替换，不要求修改任务、存储和界面核心模块。
16. 20 万行模拟导入满足第 9 节规定的基准性能指标。

## 13. 实施前技术验证

正式铺开界面和任务系统前，先完成一个受控的小规模百度适配器验证：

1. 验证 WebView2 扫码登录和会话读取在 Windows 10/11 上可行。
2. 识别运行所需的百度官方域名清单，并验证导航限制不会破坏登录。
3. 使用用户自有的合法测试链接验证分享信息读取、提取码处理、目录选择和整条链接转存。
4. 确认百度当前对同名资源、目录合并和响应错误码的真实行为。
5. 验证登录失效、验证码和频率限制能够被识别并转为暂停状态。
6. 将观察到的请求和响应语义收敛到 `IBaiduNetdiskAdapter`，不得让网页字段或接口细节泄漏到 UI、任务或数据库层。

如果扫码会话无法安全传递、整条链接转存不可稳定确认，或必要行为只能依赖规避平台安全措施，则停止正式实现并回到设计评估，不继续扩大开发范围。

## 14. 明确不在第一版范围内

- 其他网盘
- 跨网盘下载后再上传
- 分享链接内的部分文件选择
- 同一条链接同时转存到多个账号
- 自动处理验证码
- 绕过百度风控、限速或会员限制
- 云端同步账号凭证或任务数据
- 注册、会员、支付、激活码和自动更新服务
- macOS、Linux、移动端和网页版
