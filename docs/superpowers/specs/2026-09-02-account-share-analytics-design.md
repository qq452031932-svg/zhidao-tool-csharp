# 账号分享数据设计

日期：2026-09-02  
状态：独立规范复核通过，待用户审阅本文后编写实施计划

## 背景

现有“链接监控”页面面向外部分享链接，提供开始、暂停、间隔检查和转到批量转存等能力。实际需求不同：用户要查看自己百度网盘账号已经分享出去的全部链接，以及每条分享的转存、浏览和下载表现。这不是持续监控任务，而是按需同步的账号分享数据中心。

## 目标

1. 自动读取左侧当前选中百度账号在“我的分享”只读接口中可返回的全部分页记录，包括本软件创建和此前手动创建的分享。
2. 展示每条分享的有效状态、分享时间、分享链接，以及转存、浏览、下载三类只读统计。
3. 对每类指标展示历史累计、今日相对昨日的新增变化，以及最近五个自然日的每日数量。
4. 支持按历史累计和各日数值升序或降序排列。
5. 进入页面时同步一次，并提供“刷新数据”按钮；不定时轮询，不在软件关闭后运行后台任务。
6. 多账号数据严格隔离，切换账号后展示对应账号的数据。

## 非目标

- 不监控别人的分享链接是否新增文件。
- 不取消分享、删除分享、重新分享或修改提取码。
- 不提供十分钟轮询、后台常驻或系统计划任务。
- 第一版不展示分享内容的完整文件目录。
- 第一版不提供近五日合计列；“历史累计”保留为账号接口返回的历史累计总量。
- 不申请或依赖企业开放平台分享能力。

## 方案选择

采用现有扫码登录得到的加密 CK，通过百度账号网页端的只读接口在后台同步“我的分享”及统计数据。

选择理由：

- 不需要打开或控制外部浏览器。
- 与现有账号登录、会话失效和重新扫码流程一致。
- 仅在进入页面或用户主动刷新时发起请求，电脑和网络负担低。
- 百度开放平台的分享能力主要面向企业开发者，公开能力未明确覆盖个人账号每条分享的浏览、下载和转存统计。

已拒绝的替代方案：

1. 浏览器页面读取：速度慢、窗口干扰大、页面改版后容易失效。
2. 企业开放平台：接入门槛与当前个人账号场景不匹配，且不能确认提供所需统计字段。

网页内部只读接口存在变更风险，因此接口细节封装在独立适配器中。实施第一步必须进行只读契约探测，确认分页、分享身份、状态和三类统计字段；不得在设计阶段臆造字段或写操作。

契约探测是实现的 go/no-go 门槛：只有接口能稳定返回当前账号“我的分享”的完整分页、稳定分享身份以及转存、浏览、下载三类累计统计时，才进入正式实现。本文中的“全部分享”特指接口当前可返回的全部记录，加上软件首次成功见到后保存在本地的历史快照；对于首次使用软件前已被彻底删除、且百度接口不再返回的分享，软件不能恢复，也不得宣称已经覆盖。

## 页面设计

功能导航中的“链接监控”改名为“分享数据”。旧页面的开始、暂停、停止、检查间隔、粘贴链接和转到批量转存控件全部移除。

页面结构：

1. 顶部状态栏
   - 当前账号名称。
   - 最后成功同步时间。
   - “刷新数据”按钮。
   - 同步中状态和安全的失败提示。
2. 汇总区
   - 分享总数。
   - 有效数量。
   - 失效数量。
3. 指标切换
   - 转存。
   - 浏览。
   - 下载。
4. 筛选区
   - 标题搜索。
   - 全部、有效、失效状态筛选。
5. 数据表格
   - 标题。
   - 状态。
   - 分享时间。
   - 历史累计。
   - 新增。
   - 今天。
   - 昨天。
   - 前三个自然日，列头显示实际日期，例如 `08-31`、`08-30`、`08-29`。
   - 链接操作“打开”。

“打开”使用系统默认浏览器打开该行对应的分享链接，不在应用内修改任何分享状态。

## 排序与显示规则

- 历史累计、今天、昨天和三个日期列均支持升序与降序排列。
- 新增列也支持升序与降序排列。
- 无论升序还是降序，缺失值 `--` 始终排在所有有效数值之后；有效数值相同时按分享时间从新到旧，再按稳定分享身份排序，保证结果确定。
- 默认排序为分享时间从新到旧。
- 切换转存、浏览或下载指标时保留搜索词和状态筛选，排序重置为历史累计从高到低。
- 正新增显示红色，负新增显示绿色，持平显示 `--`。
- 缺少可信快照的数值显示 `--`，不使用 `0` 冒充。
- 大数值使用千位分隔符，原始数值仍用于排序。

## 指标口径

对每条分享、每类指标分别维护累计快照。三类指标使用相同计算规则。

- `历史累计`：本次同步返回的当前历史累计总量。
- `今天`：今天产生的数量。
- `昨天`：昨天产生的数量。
- 其他日期列：对应自然日产生的数量。
- `新增`：`今天 - 昨天`，允许正数、负数和持平。

所有自然日和快照归日统一使用 `Asia/Shanghai` 时区，以北京时间 00:00 为日界线。今天或昨天任一值缺失时，`新增` 显示 `--`。

数据口径优先级：

1. 如果只读接口直接返回可信的自然日统计桶，直接保存并展示这些日统计。
2. 如果接口只返回累计数，则用每天最后一次成功同步的累计快照计算日数量：`某日末累计 - 前一日末累计`。

累计快照推导存在客观限制：应用不定时运行时，今天的数量实际是“当前累计减去昨天最后一次成功同步的累计”。界面通过提示说明其基于本地快照，不宣称是百度午夜结算值。

以下情况日数量显示 `--`：

- 缺少前一日可信快照。
- 当前累计小于前一日累计，可能发生统计重置或分享身份变化。
- 分享链接重新生成后无法证明仍是同一分享身份。
- 接口返回的数据不完整或字段类型不合法。

## 数据与组件边界

### 账号分享只读客户端

职责：

- 使用当前账号的受保护会话调用百度只读接口。
- 分页读取全部分享记录，不能只取第一页。
- 将外部响应映射为稳定的内部模型。
- 识别登录失效、限流、分享失效和响应契约变化。

约束：

- 只允许 GET 或经确认无副作用的只读请求。
- 不暴露 CK、BDUSS、STOKEN 或完整响应到日志。
- 不实现取消分享、重新分享等方法。

### 分享数据同步服务

职责：

- 接收当前账号 ID 并执行一次完整同步。
- 串行读取分页，避免并发放大账号风险。
- 所有暂时性只读请求（包括分享分页及可能独立读取的统计请求）均最多自动重试一次，仍失败则结束本次同步。
- 只有完整分页及其全部统计读取成功后才提交本次快照，避免把部分数据当成账号全量。
- 接口明确返回失效状态的记录显示为“失效”，并计入失效数量。
- 在一次完整成功同步中未返回、但本地曾存在的记录只做本地留档，不推断为失效，不出现在当前列表、总数、有效数或失效数中；如果后续接口再次返回，则恢复到当前列表。同步失败时不执行此规则，继续显示上次成功同步的完整列表。

### 本地分享数据存储

至少保存：

- 账号 ID。
- 百度侧稳定分享身份。
- 标题、分享链接、分享时间、有效状态。
- 转存、浏览、下载三个累计值。
- 每次成功同步的时间和当天快照。
- 最近五日展示所需的日统计；历史累计长期保留。

账号 ID 必须参与所有主键和查询条件，防止多账号串数据。数据库不保存 CK 明文。

### 分享数据视图模型

职责：

- 监听左侧当前账号切换。
- 首次进入页面时同步一次。
- 响应“刷新数据”命令。
- 从本地快照生成五日列、新增值、汇总、筛选和排序结果。
- 同步失败时继续展示上次成功数据。
- 每个账号同一时刻只允许一个同步任务。账号切换或新一代刷新发生后，旧请求可以安全结束，但其结果只能写入请求所属账号，且不得刷新当前账号页面；同一账号的迟到旧代结果不得覆盖较新的成功结果。

## 同步流程

1. 用户进入“分享数据”页面。
2. 页面立即加载该账号的本地缓存，避免空白等待。
3. 如果本次进入尚未同步，则开始一次只读同步。
4. 客户端逐页读取分享记录与统计。
5. 每页响应先做完整契约校验，不记录敏感原文。
6. 全部分页成功后，在一个本地事务中更新分享记录和快照。
7. 页面刷新汇总、当前指标和排序结果，并记录最后成功同步时间。
8. 用户点击“刷新数据”时重复步骤 4 至 7。

同一次页面停留期间不会自动再次同步。离开再进入页面时重新同步一次。

## 错误处理

- CK 失效：提示“账号登录已失效，请重新扫码”，保留旧数据。
- 百度安全验证：提示需要完成账号验证，不尝试绕过。
- 暂时性网络失败：当前页重试一次，失败后结束同步并保留旧数据。
- 限流：显示“同步过于频繁，请稍后重试”，不连续重试。
- 单条数据损坏：如果无法安全识别分享身份，则整次同步不提交；如果仅某个统计值缺失，则该值显示 `--`，记录本身可保留。
- 分页中途失败：不提交部分全量结果，不把未读取页面上的链接标记失效。
- 接口契约变化：返回安全错误码并停止同步，日志不得包含 Cookie 或完整分享链接。

## 安全边界

- 整个模块只读，不提供远端写入接口。
- 所有账号请求复用现有加密会话解析，不新增明文 Cookie 文件。
- 完整分享链接属于用户数据，应用界面可以显示和打开，但诊断日志、测试文档和异常信息必须脱敏。
- “打开”前必须校验为 HTTPS 且主机属于允许的百度网盘分享域名；异常协议、非允许主机或无法解析的地址拒绝交给系统处理。
- 真实验收只记录账号内分享数量、分页数量、指标字段是否存在和计算校验结果。
- 打开链接是明确的用户点击动作，不在同步期间自动访问每个公开分享页。

## 测试与验收

自动测试至少覆盖：

1. 多页分享记录完整同步，页码或游标不重复、不遗漏。
2. 三类累计值解析和异常字段拒绝。
3. 历史累计、五个自然日、缺失快照及 `新增=今天-昨天` 的计算。
4. 累计值减少时显示 `--`，不生成虚假负日统计。
5. 全部数值列的升序和降序排列。
6. 指标切换后筛选保留、排序重置。
7. 多账号数据隔离。
8. CK 失效、限流、网络失败一次重试和分页中途失败的原子性。
9. 同步失败时旧数据仍可见。
10. 客户端协议测试证明不会调用远端写操作。
11. 导航名称、页面控件和“打开”动作的界面测试。
12. 同账号重复刷新单飞、账号切换及迟到请求隔离。
13. `Asia/Shanghai` 自然日边界、缺失值排序固定在末尾，以及今天或昨天缺失时新增为 `--`。
14. 完整同步缺失记录只留档不误判失效，重新出现时可恢复。
15. “打开”只接受允许的百度 HTTPS 分享地址，拒绝其他协议和主机。

真实只读验收使用当前已登录账号：

- 进入页面后只同步一次。
- 能读取全部分页并显示总数。
- 手动刷新一次后更新最后同步时间。
- 三个指标可切换，数值列可双向排序。
- 打开操作对应正确分享链接。
- 不取消、不修改、不重新生成任何分享。

## 迁移与兼容

- 旧 `LinkMonitoring` 本地 JSON 数据不导入新模块，因为其记录的是外部链接且语义不同。
- 第一版保留旧数据文件但不再读取，避免无授权删除用户历史；后续设置中心可提供明确的清理动作。
- 新功能使用独立数据库表和服务边界，不复用旧的定时监控状态机。

## 完成标准

- 当前账号全部分享可按需同步，且无浏览器窗口。
- 统计和五日数据符合本文口径。
- 所有要求的排序、筛选和账号切换可用。
- 失败不清空缓存、不泄露会话、不产生远端写入。
- 自动测试和当前账号真实只读验收通过。
