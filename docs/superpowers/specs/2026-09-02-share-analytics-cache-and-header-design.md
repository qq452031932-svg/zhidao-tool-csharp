# 分享数据缓存与表头优化设计

## 目标

优化“分享数据”表格的可读性，并避免每次进入页面都完整读取百度网盘分享列表。页面优先显示持久化缓存；只有首次无缓存、缓存达到 23 小时或用户手动刷新时才访问远端。

本轮不接入 OTA 更新，只记录后续推荐路线。

## 已确认交互

### 表头

- 使用扁平表头，不再把每个可排序列显示成独立按钮。
- 表头统一浅灰背景和细分隔线。
- 当前排序列的表头与整列使用浅黄色背景，并显示升序或降序箭头。
- 保留标题、状态、分享时间、历史累计、新增、今天、昨天、前三个日期和链接列。
- 数值保持右对齐；新增值继续使用强调色；“打开”保持明确的链接操作样式。

### 缓存状态

- 页面状态区显示数据来源、最后成功同步时间和缓存条数，例如：`本地缓存｜更新于 2026-09-02 16:00｜1,286 条`。
- 无缓存时显示首次同步状态。
- 后台同步期间继续显示旧缓存，不清空表格。
- 同步失败只显示稳定中文提示，保留旧缓存及其最后成功同步时间。

## 缓存与刷新规则

1. 缓存有效期以账号在数据库中的“最后成功同步时间”为起点，不以软件启动时间为起点。
2. 首次选中一个从未成功缓存的账号时，自动执行一次完整同步。
3. 后续启动恢复上次查看的账号，并立即读取该账号的 SQLite 完整快照，不主动访问远端。
4. 当缓存年龄达到 23 小时时，自动执行一次后台同步：
   - 启动时缓存已经达到 23 小时，显示旧缓存后立即同步；
   - 启动时缓存尚未达到 23 小时，使用一次性延时任务等待剩余时间；
   - 不使用分钟级轮询或周期性页面刷新。
5. 用户点击“刷新数据”时立即执行完整同步，不受缓存年龄限制。
6. 只有完整分页同步成功并完成原子提交后，才更新缓存内容和最后成功同步时间。
7. 手动或自动同步失败时不更新时间；后续重新进入页面、重新启动或下一次手动刷新可以再次尝试。
8. 手动刷新成功或自动同步成功后，重新从该成功时间计算 23 小时。
9. 同一账号同一时刻最多一个同步任务。手动刷新遇到正在运行的自动同步时复用或等待该任务，不启动第二个全量请求。
10. 切换账号或离开页面时取消当前页面的一次性延时任务；远端迟到结果不得覆盖当前账号页面。

## 上次查看账号

- 持久化最后一次被用户选中的分享数据账号 ID。
- 下次启动时，如果该账号仍然存在且可用，则自动恢复选择。
- 若记录账号已删除或不可用：仅有一个可用账号时自动选择该账号；有多个账号时保持未选择状态，等待用户选择。
- 复用左侧现有账号选择状态；恢复上次查看账号时不创建任务，也不修改已经确认的批量任务。

## 数据流

### 页面进入

1. 恢复上次查看账号。
2. 从 SQLite 加载该账号最后一次完整快照。
3. 立即投影并显示缓存数据。
4. 无快照时启动首次同步；有快照时根据最后成功同步时间计算是否已达到 23 小时。
5. 已过期则后台同步；未过期则安排一次性延时任务。

### 手动刷新

1. 取消尚未触发的一次性延时任务。
2. 进入单账号同步门闩。
3. 完整分页读取远端数据。
4. 成功后原子替换 SQLite 快照并刷新页面。
5. 失败后保留旧快照并重新安排合理的后续尝试时机。

## 错误与安全边界

- 分享数据工作区保持只读，不执行取消分享、删除、重建或其他远端写操作。
- 远端返回不完整页、超过分页上限、会话不可用或请求失败时，不提交半截缓存。
- 状态提示不暴露 Cookie、请求参数、异常堆栈或本地敏感路径。
- 自动同步只在软件运行期间发生；软件关闭后不保留后台进程。

## 测试

- 有缓存进入页面只加载缓存，不调用远端同步。
- 无缓存进入页面自动同步一次。
- 缓存未满 23 小时安排剩余时间的一次性任务。
- 缓存已满 23 小时立即同步。
- 手动刷新忽略缓存年龄并在成功后重置计时。
- 同步失败保留旧缓存和旧时间。
- 自动同步与手动刷新单飞。
- 离开页面、切换账号及关闭窗口取消延时任务，迟到结果不串账号。
- 启动恢复上次查看账号；失效账号按单账号或多账号规则降级。
- XAML 验证表头不使用按钮外框，排序列具有高亮触发器和方向标识。
- 实机验证首次无缓存、缓存启动、23 小时边界和手动刷新四种状态。

## 后续 OTA 路线（不在本轮实现）

采用 Velopack 与国内对象存储或现有 HTTPS 静态站点：

- 发布脚本生成 Setup、完整包、增量包和版本索引。
- 先上传版本文件，最后原子发布版本索引，防止用户读到不完整版本。
- 软件启动时异步检查小型版本索引，设置中心提供“检查更新”。
- 发现新版后显示当前版本、最新版本和更新说明；用户点击后下载、校验、应用并重启。
- 本地 SQLite、账号会话和日志继续位于 LocalAppData，不放入会被更新替换的程序目录。
- 正式分发前为安装器和可执行文件配置代码签名，并保留上一稳定版本供回滚。
