# 扫码自动获取 CK 设计

## 目标

账号添加或登录失效时，软件只弹出一个应用内百度网盘登录窗口。用户扫码并在手机确认后，程序自动验证登录状态、读取当前窗口自己的 Cookie、验证账号身份、使用 Windows DPAPI 加密保存，并自动关闭登录窗口。后续批量任务不依赖鼠标、键盘、窗口坐标或外部 Chrome 界面控制。

## 范围

本阶段只完成登录会话获取与保存：

- 新增账号和重新登录统一使用应用内 WebView2 扫码窗口。
- 只有页面稳定进入 `https://pan.baidu.com/disk/main`，并同时存在非空 `BDUSS`、`STOKEN` 时才开始捕获。
- 捕获后调用现有身份接口验证百度账号；重新登录时必须与所选账号一致。
- Cookie 只保存在当前 Windows 用户可解密的 DPAPI 密文中，不展示、不写日志、不支持明文导出。
- 登录窗口使用一次性的隔离 WebView2 配置目录；登录尝试的所有权令牌只保护该临时目录，不替换账号记录的所有权。成功、取消或失败后都安全清理，避免旧账号 Cookie 和配置目录所有权冲突。
- 成功保存后自动关闭窗口并刷新左侧账号信息。
- 同一目标账号同一时刻只允许一个登录尝试；旧尝试的迟到结果不得覆盖较新的有效 CK。

本阶段不修改百度转存、分享接口协议。CK 登录验收通过后，再单独修复后台转存与分享。

## 数据流

1. 用户点击“添加百度账号”或“重新登录”。
2. 创建一次性登录尝试 ID 和隔离 WebView2 配置目录。
3. 打开百度网盘登录页，用户扫码确认。
4. 每 700ms 观察顶层地址和 Cookie；登录条件连续稳定 3 秒后进入捕获。
5. 过滤无效 Cookie，创建未绑定会话并调用身份接口验证。
6. 新账号仅在百度 UID 不存在时创建账号记录；重复 UID 拒绝创建第二个账号。重新登录复用原账号记录，校验百度 UID 与原账号一致，只原子更新加密会话和捕获时间。
7. 保存前再次确认登录尝试仍是该账号的当前尝试，通过 DPAPI 加密保存会话，刷新头像/容量。
8. 停止导航和轮询，在 WebView2 控制器仍可用时先清除其 Cookie 数据，再释放 WebView2 并删除临时目录；删除失败时移动到应用隔离的待清理区，由下次启动继续清理。

## 失败处理

- 未扫码或用户关闭：不修改现有 CK。
- 身份不一致：拒绝覆盖原账号 CK；停止当前 WebView2 导航，在控制器仍可用时清除 Cookie，再释放 WebView2 并重新创建一次性配置目录，然后显示新的二维码，避免错误账号保持登录。
- Cookie 不完整或身份接口失败：继续等待，不保存半成品。
- 同账号重复打开登录窗口：保留最新尝试，取消旧尝试；旧尝试即使迟到完成也不能写入数据库。
- 临时目录无法安全清理：先在 WebView2 仍可用时清除 Cookie，再释放 WebView2，然后将目录移动到仅当前 Windows 用户可访问的待清理区；不删除无法证明归属的目录，并在下次启动继续清理。
- CK 过期：后台任务标记账号需要重新登录，不自动弹窗抢焦点。

## 验收标准

- 新增账号扫码成功后自动关闭窗口，数据库存在 DPAPI 密文且没有明文 Cookie。
- 所选账号重新扫码后 CK 捕获时间更新；扫入其他账号时原 CK 不变。
- 重复 UID 不会创建第二个账号；两个并发登录尝试中只有最新尝试可以写入。
- 取消、失败、错误账号和重复触发不会覆盖有效会话；WebView2 释放后临时配置目录中不留下可继续使用的登录状态。
- 普通批次执行期间不调用任何桌面界面控制能力。
