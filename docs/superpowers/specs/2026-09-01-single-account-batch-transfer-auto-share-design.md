# 单账号批量转存与自动分享设计

日期：2026-09-01

## 1. 目标

第一阶段完成一条可无人值守的百度网盘主流程：

```text
粘贴多条分享链接或导入 Excel
  → 使用左侧选中的一个已登录账号
  → 转存到统一百度网盘目录
  → 每条转存成功后自动创建永久分享
  → 自动生成四位提取码
  → 保存新分享链接与提取码
  → 批次结束后自动导出结果表
```

本阶段不实现多账号复制、多账号分流、广告插入、文件排除、数据统计或设置中心。

## 2. 用户体验

### 2.1 输入与账号

- 同时保留直接粘贴多条百度分享链接和导入 Excel 两种入口。
- 每条链接可携带独立提取码。
- 同一批次内，规范化分享标识和提取码都相同的重复输入只执行一次；“同名保留两份”指目标目录已有同名对象，不表示同一输入要重复执行。
- 左侧当前选中的账号就是本批唯一执行账号；未选账号时不能开始。
- 批量转存页不显示单账号、多账号复制、多账号分流等模式按钮。

### 2.2 目标目录

- 用户为整个批次设置一个百度网盘保存目录，默认 `/`。
- 目录不存在时逐级创建，存在时直接使用。
- 同名文件和文件夹一律保留两份，由百度产生实际的新名称，例如 `名称(1)`、`名称(2)`。
- 结果以百度实际返回或重新读取确认的名称为准，不由客户端猜测最终编号。

### 2.3 自动分享与导出

- 转存成功后必须自动分享，不提供开关。
- 分享固定为永久有效、不限次数、自动生成四位提取码。提取码使用密码学安全随机数生成，字符集固定为小写英文字母 `a-z` 和数字 `0-9`，长度必须恰好为 4。
- 一条原链接包含几个最外层文件或文件夹，转存后的新分享就必须包含对应的几个对象；结果表仍按原链接记录一行。
- 分享必须绑定该条转存实际产生的完整对象集合，数量和远端对象标识都要一致，不能仅按名称搜索。
- 默认结果目录为 `文档\百度批量转存结果`，用户可以更改并持久保存该设置。
- 批次结束后自动生成带日期时间的结果文件，不要求用户等待后再点击导出。

### 2.4 界面

顶部只保留：

- 粘贴内容；
- 选择 Excel；
- 百度保存目录；
- 并发数（1–3，默认 2）；
- 开始转存。

开始前显示一次简短确认，包含链接数量、账号、百度保存目录、自动分享和本机结果目录。

结果表显示：

- 原分享链接；
- 百度实际保存名称；
- 百度保存目录；
- 新分享链接；
- 新提取码；
- 状态（成功或失败）；
- 失败原因。

运行区提供暂停、继续和只重试失败项。界面不向用户展示“待确认”等中间术语。

一条原链接包含多个最外层对象时，“百度实际保存名称”在界面中每行显示一个名称；Excel 的同一单元格使用换行保存这些名称，顺序与本次操作返回的对象集合顺序一致。

## 3. 执行架构

### 3.1 复用现有组件

继续使用现有的：

- 文本和 Excel 导入、规范化、去重与分页；
- SQLite 批次、资源、操作和结果持久化；
- 左侧账号选择及加密登录会话；
- 任务暂停、继续、失败重试和结果投影；
- Excel 结果导出框架。

不另建旁路任务系统，不重写已有导入和结果页面。

### 3.2 受控浏览器会话与后台请求适配器

登录、验证码和安全验证继续由应用拥有的受控 Chromium 完成。登录成功后浏览器自动最小化并保持运行；正常转存和分享不逐项点击网页，而是在该账号的浏览器会话内调用经过核验的百度同源接口。这样既复用真实登录状态，又不把 Cookie 或令牌导出给普通业务代码。

适配器只允许预定义的百度 HTTPS 主机、固定接口、固定字段和有界响应，不接受调用方传入任意 URL、脚本或选择器。每次请求都绑定当前批次选中的准确账号身份，并在提交远端写入前再次核对浏览器中的百度账号身份。

若某个已核验的接口因百度页面调整而暂时不可用，可以使用现有受控网页流程作为兼容后路，但必须复用相同的操作意图、对象映射和持久化结果契约。兼容后路不允许绕过账号校验、对象数量校验或重复提交保护；启用兼容后路期间，全局远端写入并发必须自动降为 1。

转存工作器对每条资源按以下顺序执行：

1. 校验账号会话与分享链接。
2. 处理该链接的提取码。
3. 确保目标目录存在。
4. 持久化本次操作标识和提交意图。
5. 以“保留两份”策略提交转存。
6. 从该次提交的权威响应或操作级结果查询中取得实际目标对象标识和最终路径；禁止用整个目录的前后差异猜测归属。
7. 核对目标对象数量与原分享最外层对象数量一致，持久化转存结果，并把这组准确对象写入分享队列。

分享工作器随后按以下顺序执行：

1. 读取已持久化的完整目标对象集合。
2. 再次核对对象数量、远端标识和所属账号。
3. 对该完整集合创建永久分享和四位提取码。
4. 持久化分享链接、提取码和整条资源的最终状态。

所有远端请求均使用超时、响应大小上限、敏感字段脱敏和账号绑定校验。

并发操作即使写入同一目录，也必须依靠每次提交返回的操作标识、目标路径或对象标识完成绑定。若百度没有返回足以证明归属的操作级结果，该次不能进入分享阶段；按第 4.3 节重试后仍无法取得权威映射则标记失败。

### 3.3 持久化双队列、并发和限流

- 使用独立的持久化转存队列和分享队列，不采用“全部转存完成后才开始分享”的两阶段批处理。
- 一条资源的转存一经确认并落盘，就立即进入分享队列；后续资源的转存可以与前面资源的分享重叠执行。
- 转存和分享共用同一个全局远端写入并发限制，默认 2，用户可在 1–3 之间调整。并发数表示同时进行的百度远端操作总数，而不是为两个队列各自分配一套并发额度。
- 调度器优先防止分享积压；当未分享条目达到有界阈值时，暂停领取新的转存任务，先消化分享队列。
- 同一条资源内部仍严格保持“确认转存后才能分享”的顺序。
- 遇到限流或连续临时网络错误时自动把全局并发降到 1，并采用指数退避。
- 登录失效或百度安全验证会暂停两个队列，不再领取新任务，并恢复显示受控浏览器。
- 用户完成登录或安全验证后，浏览器重新最小化，两个队列从持久化进度自动继续。

不存在可依赖的官方“分享链接转存”开放平台 QPS 承诺，因此不允许把并发提高到 3 以上。

## 4. 状态、错误和重试

### 4.1 用户可见状态

每条结果只显示成功或失败。内部阶段可以细分并持久化，但不要求用户判断内部术语。

整条成功必须同时满足：

1. 已确认转存对象；
2. 已为该对象创建分享；
3. 已保存新分享链接和提取码。

### 4.2 失败处理

- 格式错误、链接失效、提取码错误：标记失败并继续后续任务。
- 临时网络错误或限流：退避后自动重试，单个远端阶段最多 3 次。
- 登录失效或安全验证：暂停批次并提示重新登录。
- 单条失败不阻止其他链接继续执行。

### 4.3 结果不明确

用户接受“简化状态优先于绝对防重”：

- 转存提交没有明确结果时自动再提交一次。
- 第二次仍无结果就标记失败并继续。
- 第一次实际成功但响应丢失时，第二次可能生成 `(1)` 等重复对象；用户已接受此结果。
- 第二次若返回权威对象集合，只分享第二次明确返回的集合，不把第一次可能产生但无法绑定的对象混入新分享。

如果转存已确认成功但分享失败：

- 整条显示“失败：已转存，分享失败”；
- 重试失败项时只重试分享，不再次转存。

## 5. 持久化与恢复

- 每个远端阶段开始前写入本地意图，完成后立即写入结果。
- 保存实际百度对象标识、实际名称、目标目录、分享链接、提取码以及安全的失败分类。
- 软件关闭或崩溃后，不重新执行已经确认成功的转存或分享阶段。
- 转存队列和分享队列都必须落入 SQLite；不得依赖只存在于内存中的待分享列表。
- 用户暂停时停止领取新任务，正在执行的步骤完成安全落盘后停止。
- “只重试失败项”根据已持久化阶段决定从转存还是分享继续。
- 日志和导出不得包含 Cookie、令牌、完整本机敏感路径或未脱敏诊断响应。
- 自动结果导出失败不改变已完成的远端转存和分享结果；批次顶部显示“处理完成，结果文件保存失败”，并提供“重新保存结果”按钮，重试导出时不得重新执行远端操作。

## 6. 测试策略

### 6.1 离线自动化

使用固定响应和本地模拟服务覆盖：

- 文本与 Excel 多链接导入、独立提取码和去重；
- 目录逐级创建；
- 同名保留两份和实际名称记录；
- 同一输入去重与目标目录同名保留两份之间的边界；
- 默认并发 2、最大并发 3、限流后降为 1；
- 大批量输入下转存和分享可以流水线重叠执行，且分享积压达到阈值后停止领取新转存；
- 应用重启后从持久化的转存队列和分享队列分别恢复；
- 临时错误重试与登录失效暂停；
- 不明确转存的一次额外提交和最终失败；
- 单对象和多对象分享链接的完整集合绑定、数量一致性以及远端对象标识一致性；
- 并发写入同一目录时只能使用操作级权威映射，禁止使用目录差异猜测对象；
- 永久分享设置和密码学随机四位小写字母数字提取码；
- 分享失败后只重试分享；
- 重启续跑、暂停和继续；
- 结果文件自动生成且不覆盖旧文件；
- 自动导出失败后只重试导出，不重做转存或分享；
- 日志和结果脱敏。

### 6.2 真实验收

离线测试和构建全部通过后，才使用：

- 一个有剩余空间的测试账号；
- 一条可丢弃的分享链接；
- 一个明确的测试目标目录。

真实验收会修改百度网盘并创建公开分享，必须在执行前再次获得用户确认。验收顺序为单条转存、实际对象核对、自动分享、结果导出，然后才扩大到多条和并发 2。

## 7. 明确不做

- 正常转存和分享不逐项点击百度网页；受控浏览器只承载登录会话并在后台最小化运行。
- 不把浏览器 Cookie、令牌或任意脚本能力暴露给业务层。
- 不使用开放平台 OAuth 重做账号登录。
- 不开放高于 3 的单账号并发。
- 不实现多账号复制或多账号分流。
- 不允许按名称猜测分享对象。
- 不在本阶段实现其他导航模块。

## 8. 完成标准

本阶段完成必须同时满足：

1. 单账号可导入多条链接并后台转存；
2. 目标目录自动创建，同名保留两份；
3. 转存与分享使用持久化双队列流水线，共用默认并发 2，并在限流时自动降速；
4. 每条成功转存后自动生成永久分享和四位提取码；
5. 单条失败不阻塞后续任务，失败项可按正确阶段重试；
6. 批次结果自动导出到持久化的本机结果目录；
7. 软件重启后能恢复进度；
8. 相关测试、解决方案构建和脱敏检查全部通过；
9. 未经再次确认，不执行真实百度网盘写入验收。
