# 双工作区与 WebView2 人工模拟设计

日期：2026-08-24

## 目标

把当前暴露“草稿、创建任务、批量预检”等内部概念的五步向导，改成用户能直接理解的两个工作区：

- **转存**：导入外部百度分享链接，保存到选定账号，并可在每条转存成功后自动分享对应的实际资源；
- **分享**：从已登录账号自己的网盘中选择已有文件或文件夹，批量创建分享，并把结果保存到用户选择的本机目录。

转存和分享均使用用户可见、用户可接管的 WebView2 模拟百度官方网页操作，不要求百度网盘开放平台权限，不调用未经现场确认的隐藏写接口，不绕过扫码、验证码、安全验证、限流或账号限制。

## 用户界面

左侧工作区只保留两个入口：

1. `转存`
2. `分享`

账号登录、账号管理和刷新账号继续放在窗口右上角。历史结果、当前进度、暂停、继续和失败重试显示在当前工作区下方，不再设置独立的“创建任务”入口。

内部仍使用现有批次、操作、持久化和崩溃恢复模型，但用户界面不显示“草稿、创建任务、批量预检、适配器”等开发术语。

### 转存工作区

按一个页面完成：

1. 粘贴百度分享文案或选择 Excel；
2. 显示解析后的资源行和可修正的链接、提取码；
3. 选择单账号、多账号复制或多账号分流；
4. 选择每个参与账号的网盘保存目录；
5. 勾选是否“转存完成后自动分享”；
6. 若启用自动分享，选择分享结果在本机的保存目录，并设置随机或固定提取码；
7. 点击`开始转存`。

链接检查在开始前后台自动执行。只有需要用户处理的无效链接、缺少提取码、账号失效或冲突才显示明确提示，不设置单独的“批量预检”步骤。

### 分享工作区

按一个页面完成：

1. 选择一个或多个已登录账号；
2. 在账号自己的百度网盘中选择一个或多个已有文件、APK 或文件夹；
3. 每个选中资源分别成为一条待分享记录；
4. 设置永久有效、随机或固定提取码；
5. 必须选择本机分享结果保存目录；
6. 点击`开始分享`。

同一批选择中的每个文件或文件夹默认分别生成对应的分享结果。用户没有选中资源或没有选择本机结果目录时，开始按钮不可用。

## 精确资源对应关系

每条原始输入记录必须和实际转存结果建立持久、可核对的对应关系：

```text
原始输入行
  -> 参与账号
  -> 本次转存产生的实际顶层资源集合
  -> 自动分享操作
  -> 新分享链接、提取码和结果状态
```

- 原链接代表文件夹时，自动分享本次实际转存的对应文件夹；
- 原链接代表 APK 或其他单文件时，自动分享本次实际转存的对应文件；
- 一个原链接包含多个顶层资源时，把该顶层资源集合保持为同一条新分享：页面中同时选中这一组精确资源，使用普通“分享”创建一个包含整组资源的链接，不使用会为每项分别生成链接的“批量分享”；
- 不得分享整个上级保存目录；
- 不得按名称、目录时间、页面成功文字或“看起来相同”猜测对应关系；
- 无法从页面结构、页面返回的稳定资源标识或转存后的可核对列表确定实际资源时，状态保持“结果待确认”，自动分享不得开始。

## WebView2 人工模拟架构

每个百度账号继续使用现有独立 WebView2 Profile。扫码登录后的会话只保存在本机加密存储和该账号 Profile 中。

自动化执行层分为四个独立组件：

1. **页面导航器**：只允许百度官方 HTTPS 主机，打开外部分享页、账号网盘目录和分享页面；
2. **页面状态识别器**：通过可见文本、无障碍角色、稳定 DOM 属性和有界的页面状态读取判断当前步骤；
3. **人工操作执行器**：点击官方页面的保存、目录选择、全选、批量分享、永久有效、创建链接和导出按钮；
4. **下载与证据协调器**：接管 WebView2 下载事件，把百度生成的分享结果文件保存到用户选择的本机目录，并在文件完整、格式可读且属于当前批次后才标记成功。

优先使用语义和稳定属性定位按钮，保留少量经过现场验证的候选定位器。禁止依赖固定屏幕坐标。每个动作后必须等待页面出现可验证的新状态，不能只因为点击没有抛错就判定成功。

页面执行器允许只读观察官方页面已经加载的 DOM 属性和网络响应，以取得稳定资源标识、提交接受状态和结果关联证据，但所有写操作必须由可见页面点击触发。只读观察不得记录请求头、Cookie、完整响应正文或无关账号数据。

## 浏览器写操作提交边界与恢复

每次会产生外部变化的页面点击都使用以下持久化状态机：

```text
准备中
  -> 已保存提交前基线
  -> 正在点击提交
  -> 结果待确认
  -> 已确认成功 / 已确认未提交 / 需要用户判断
```

提交前基线至少包含当前操作代次、账号、目标目录、精确待处理资源集合，以及页面当前可见的稳定资源标识或已有分享集合摘要。基线、操作状态和内部幂等键必须在点击前持久化。

点击保存或创建分享以后，即使页面关闭、超时或程序崩溃，也不得立即重复点击：

- 转存恢复先重新打开目标目录，使用提交前基线和稳定资源标识核对本次新增的精确顶层资源集合；唯一匹配则确认成功，明确没有提交且页面给出可重试证据时才重试，多个可能结果或证据不足则保持“结果待确认”；
- 分享恢复先检查提交前已有分享基线、当前账号的分享记录和当前精确资源集合；唯一的新分享匹配则确认或复用，明确未提交且没有最终一致性等待风险时才重试，其余情况要求用户判断；
- 下载或本地持久化失败不等于远端创建失败。此时只恢复结果获取和导出，不重新创建分享；
- 任何迟到页面事件都必须同时匹配批次、账号、操作 ID 和代次才能更新状态。

### 转存自动化

对每条操作：

1. 在对应账号 WebView2 中打开外部分享链接；
2. 等待分享内容和提取码状态稳定；
3. 用户遇到验证码或安全验证时暂停并接管；
4. 点击保存到网盘并选择目标目录；
5. 等待官方页面明确接受；
6. 在目标目录中核对本次实际顶层资源集合和稳定资源标识；
7. 持久化精确结果；
8. 若启用自动分享，把该精确资源集合送入分享队列。

### 分享自动化

参考 `D:\自动分享\baidu\baidu\integrated\one_click_baidu_pan_pipeline.py` 已验证的行为顺序，但在 .NET WebView2 内重新实现：

1. 打开包含待分享资源的网盘目录；
2. 定位并选中当前操作对应的准确文件或文件夹；
3. 点击批量分享；
4. 选择永久有效；
5. 设置随机或固定提取码；
6. 点击批量创建链接；
7. 等待结果弹窗和当前项目成功状态；
8. 点击导出链接；
9. 验证下载文件完整并移动到用户选择的本机目录；
10. 解析当前操作的分享结果并持久化。

参考项目仅作为操作顺序、候选定位器、等待条件、分页加载、空目录检查和下载完成判断的依据。不复制它的卡密授权、本地配置、运行日志、状态文件、独立 Python 运行时或外部 Chrome 调试端口设计。

自动分享和分享工作区使用不同的组合语义：

- 自动分享的一条原始输入记录对应一个精确资源集合；集合含多个顶层资源时，创建一个整组分享；
- 分享工作区中用户分别选中的文件或文件夹各自生成一条分享记录；第一版每次页面提交只处理一个内部分享操作，以避免重名资源、页面排序和官方导出行顺序造成错误对应；
- 页面批量能力只有在现场验收确认每一行都含稳定、可持久关联的资源标识后才能优化为多项一次提交，不能仅按文件名或行序对应。

## 多账号和调度

- 每个账号一个隔离的 WebView2 Profile 和操作队列；
- 同一账号同一时间最多一个页面写操作；
- 第一版为了稳定性，全局按队列顺序显示并执行一个可见浏览器操作；
- 多账号复制或分流仍由现有分配模型决定，页面执行器只处理已明确绑定的账号操作；
- 分享工作区的资源选择必须在某个明确账号的 WebView2 中进行；每个待分享操作持久绑定 `AccountId + 精确资源集合`，不能把一个账号的资源标识复制给另一个账号；
- 多账号分享界面按账号分组显示已选资源。切换账号后进入该账号自己的网盘选择，不提供跨账号自动复制选择；
- 某账号需要扫码、验证码或安全确认时，全局页面写队列暂停并保持该账号 WebView2 可见，直到用户处理、跳过或取消；用户接管期间不得在后台切换 Profile 执行其他写操作；
- 自动分享依赖对应转存操作达到精确成功，不得提前执行。

## 结果文件

### 转存且自动分享

另存新的 Excel，不覆盖源文件，并至少包含：

- 原始全部列；
- 原分享链接；
- 每个参与账号一组动态结果列：实际转存账号、转存状态、新分享链接、新提取码和分享状态。

一条原始输入始终输出一行。多账号复制时，各参与账号分别填写自己的动态列；多账号分流时只填写实际负责账号的动态列，其他参与账号列留空。该布局沿用现有动态账号结果列模型。

### 只转存

转存完成后直接显示完成状态。用户可选择另存转存结果；不生成虚假的分享列值。

### 只分享

第一版每个内部分享操作只向页面提交一个文件、一个文件夹或一个明确的顶层资源集合，因此页面结果与内部操作可以无歧义关联。页面显示的新链接和提取码在该操作代次内直接进入结果模型；如果官方页面提供导出文件，下载协调器把它作为当前单操作的辅助证据，不依靠文件名匹配资源。

整个用户批次完成或用户点击保存时，软件在所选本机目录生成一个汇总 Excel，一条已选资源一行，至少包含账号显示名、网盘资源名称、资源类型、新分享链接、提取码和状态。官方单操作下载文件如需保留，使用批次和操作序号命名并放在同目录的 `官方导出明细` 子目录；默认汇总文件名为 `百度分享结果_yyyyMMdd_HHmmss.xlsx`，同名时增加递增后缀，不覆盖旧文件。

## 失败、暂停和人工接管

- 页面元素未找到、页面版本变化、目录为空、下载超时或结果无法对应时暂停当前操作，保存当前阶段，不把它标记成功；
- 出现扫码、验证码、安全验证、访问限制或风控提示时显示 WebView2，并要求用户本人处理；
- 用户处理完成后从可验证阶段继续，不重复已经确认成功的转存或分享；
- 分享失败只重试分享，不重复转存；
- 页面迟到响应必须带当前批次、账号和操作代次，不能覆盖新任务状态；
- 日志只记录阶段、稳定错误码、计数和脱敏定位器名称，不记录 Cookie、请求头、响应正文、完整链接、提取码、百度用户 ID 或完整本地路径。

粘贴输入没有 Excel 原始列时，转存结果至少保存输入序号、原始文本中解析出的标题、原分享链接、原提取码和各账号动态结果列；用户选择 Excel 时保留原始全部列及顺序。

## 安全边界

- 不启动开放远程调试端口的外部 Chrome；
- 不读取用户其他浏览器的 Cookie、密码、本地存储或 Profile；
- 不把登录态从一个账号 Profile 复制到另一个账号；
- 不绕过验证码、扫码、安全验证、限流和百度风控；
- 不执行网页提供的未知脚本，只运行应用内固定、受测试、最小范围的 DOM 查询和点击脚本；
- 正式启用前必须用用户自己的无敏感测试资源完成现场验收；
- 百度页面改版导致证据不足时自动关闭对应能力，不带病继续。

## 测试与验收

自动化测试覆盖：

- 左侧只有转存和分享两个工作区；
- 转存页面不出现草稿、创建任务和批量预检入口；
- 未启用自动分享时不要求结果保存目录，完成后不进入分享队列；
- 启用自动分享时结果保存目录必填；
- 分享页面必须选择账号、网盘资源和本机结果目录；
- 文件夹、APK、普通文件和多个顶层资源保持精确对应；
- 转存失败、结果待确认和分享失败的状态隔离；
- 页面定位器多候选、页面改版失败关闭、超时、暂停与继续；
- 下载临时文件、未完成文件、旧文件和同名文件不会被误认作本次结果；
- 日志、错误、导出和 `ToString()` 不泄露敏感信息；
- Debug/Release 严格构建和现有数据库恢复测试继续通过。

现场验收至少覆盖：

1. 外部文件夹链接转存后自动分享对应文件夹；
2. 外部 APK 链接转存后自动分享对应 APK；
3. 只转存；
4. 从自己网盘选择文件和文件夹只分享；
5. 随机与固定提取码；
6. 单账号和两个隔离账号；
7. 用户处理一次登录或安全验证后继续；
8. 分享结果保存到用户选择的本机目录并可打开；
9. 页面定位器失效时安全暂停而不是误点或假成功。
