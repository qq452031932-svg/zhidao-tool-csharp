# 左侧账号容量刷新设计

## 目标

在主窗口左侧账号卡片中显示已登录百度账号的已用容量和总容量。容量刷新不是独立功能模块，不新增工作区、导航按钮或手动扫描按钮。

## 范围

- 账号登录流程完成后，为本次新增或刷新出的已登录账号查询一次容量。
- 账号从未选中变为选中时，为该账号查询一次容量。
- 账号卡片使用一行展示：`已用 {used} / {total}`。
- 查询成功后更新当前账号卡片，并把容量写回账号持久化记录。
- 查询失败时保留最近一次有效容量；没有历史数据时显示“容量未知”。
- 登录失效、需要验证、临时网络失败使用稳定的中文状态提示，不显示接口响应、Cookie、令牌或本机资料路径。
- 同一账号已有容量查询在执行时，不再次启动重复查询。

## 非目标

- 不扫描网盘文件或目录。
- 不递归统计文件大小。
- 不增加“空间扫描”页面、导航项或按钮。
- 不在本阶段修改批量转存、链接监控或其他建设中模块。
- 不把失败响应或缺失字段解释为零容量。

## 方案选择

采用现有登录会话访问百度容量接口，读取服务端返回的 `total` 与 `used` 字节值。该方案复用当前会话和网络边界，不依赖页面布局或 DOM；相比浏览器页面抓取更稳定，也能得到真实刷新值，而不是只展示数据库缓存。

容量响应必须满足：请求成功、业务错误码为成功、`total` 和 `used` 均为非负整数且 `used <= total`。任何不完整、超界或无法解析的响应都视为失败，不覆盖旧值。

## 组件与数据流

1. 容量客户端在既有百度只读适配器内实现容量查询，沿用身份查询的 Cookie 适用范围、禁止重定向、响应大小上限和错误映射。
2. 容量刷新服务按账号加载解密后的会话，调用只读适配器，并在成功时原子更新账号记录的 `CapacityTotal`、`CapacityUsed` 和验证时间。
3. 主窗口协调登录完成事件与账号选择事件。每个账号设置单独的执行中门闩，防止相同账号的登录刷新和选择刷新重叠。
4. 账号行模型提供受控的容量更新入口，并通知 `CapacityUsedText`、`CapacityTotalText` 和组合展示文本刷新。
5. 左侧账号卡只绑定组合展示文本；不出现额外操作按钮。

## 交互与错误处理

- 登录窗口关闭并成功刷新账号列表后，自动刷新相应账号容量。
- 用户选中账号时立即开始刷新；卡片保留旧容量，避免闪回“未知”。
- 成功后卡片更新为最新的 `已用 / 总容量`。
- 登录失效时提示用户重新登录；需要安全验证时提示完成验证；临时失败时提示稍后重试。
- 账号在请求期间被退出、删除或取消选中，不允许迟到结果错误更新其他账号。

## 测试与验收

- 容量接口：成功响应、字符串/数字业务码、缺字段、负数、已用大于总量、超大响应、登录失效、验证要求、限流、服务错误、取消。
- 刷新协调：登录后调用一次、未选中到选中调用一次、重复选中不调用、同账号并发合并、不同账号互不阻塞、迟到结果不串账号。
- 持久化：仅成功响应覆盖容量；失败保留旧值；重新加载后仍显示最新值。
- 界面：账号卡精确显示 `已用 {used} / {total}`；不存在“空间扫描”导航或按钮。
- 完成后运行聚焦测试、应用测试、解决方案构建和 `git diff --check`。
