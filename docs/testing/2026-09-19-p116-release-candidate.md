## 本轮修复的实质问题

### 断网被误判为未激活

服务端 `validationLease = 30 * time.Minute`。断网超过半小时，已付费用户就被判未授权并弹出激活窗——用户看到的是"你没激活"。

真正拦住盗版的是签名信封、机器绑定与服务端吊销，三者都与租约时长无关；租约时长只决定**吊销延迟**，且只对诚实用户生效（破解者直接改本地校验）。因此：

- `Startup` 操作获得 **7 天**离线宽限（`LicenseAuthorizationGate.StartupOfflineGrace`）
- `Transfer` / `Share` / `ShareAnalyticsRefresh` **维持严格**——这些操作要访问网盘，能连网盘就能连授权服务，吊销延迟因此不变
- **卡密自身的到期时间从不放宽**，过期月卡拿不到任何宽限

`AppStartupResult` 现在携带授权门的 `Code`，不再压成一个布尔，"这台机器没有卡密"与"连不上服务器"不再长得一样，**只有前者才弹激活窗**。

客户端对"服务端签发租约"的上限也从 30 分钟放宽到 7 天。它原先与服务端常量完全相等，意味着服务端一旦调整租约，所有旧客户端会把合法回复判成非法信封、当场集体锁死。这个上限本身拦不住什么：能签出更长租约的人已经握有私钥。

### 转存历史永久清不掉

两道独立的拦截叠成死锁，而界面上只有一个没有解释的灰按钮，提示语还写着"任务处理或保存期间不可清空"——在实际场景里这句话是错的。

**第一道**：任何未收尾的自动化尝试都算冲突。进程被杀会留下停在 `Preparing` 的记录，而它可证明从未提交：适配器先把 `BaselinePersisted → Submitting` 落盘再调用提交，进入 `Submitting` 又必须先处于 `BaselinePersisted`，且 schema 的 CHECK 约束保证 `ResumeStage` 只在 `UserHandoff` 时非空。这种记录不承载任何证据，现已放行；其余一律照旧拦截，包括"带着基线的 Preparing"这种自相矛盾的状态。

**第二道**：仍可安全重试的失败转存。这条守的是真东西，但唯一的出路是重试它们——**而重试入口根本没有按钮**，于是那批历史永远卡着。现改为如实计数并上报：确认框写明有几条失败项将失去重试能力，且该计数进了快照令牌，"确认的是 1 条、删掉的是另一批"不可能发生。

### 失败的转存无处重试

`RetryFailedTransferCommand` 的实现、安全判定与测试都完整，**但所有 XAML 里没有任何绑定**。已在「处理结果」标签页顶部加上「重试所选失败项」按钮。

### 未激活时点开始转存像在运行

原先只往运行日志写一行，而用户多半停在"待处理链接"上看不到任何变化，会以为任务在跑然后一直等。现在：点开始自动切到运行日志；被授权拦截时弹窗说明并**直接提供激活入口**；提示语从"联网功能暂不可用"改为指出**在哪里激活**。

成功建任务后仍交接到"处理结果"，两种结局都不会让用户对着没有变化的列表干等。

### 首页与版本号

外壳原先直接打开"监控反馈"，新用户落在一个空列表上，没有任何东西说明这是什么。首页现在承载功能说明与更新日志，版本号常驻标题栏（此前只有进设置中心才看得到，用户报问题时说不清自己在用哪一版）。

更新日志是**编译进程序的**，不读 OTA feed：feed 只在有待安装更新时才带说明，而用户想看的是自己这一版改了什么，离线也要看得到。

首页**刻意不放授权面板**——页头徽标与设置中心卡片已经各有一份，第三份只会制造三者互相矛盾的机会。也没有"最新公告"和"问题反馈"：两者都需要服务端接口，而写死的公告没人更新，比没有更糟。

## 结构性隐患

- **没装 Go**：`scripts/test_local_license_stack.ps1` 需要 Go 编译授权服务与后台，全盘搜不到 `go.exe`。这意味着**授权栈整套验收（激活、多软件授权、续期、管理员解绑、后台删卡后拒绝、离线边界）在这台机器上做不了**。交接文档里记的"1.1.2 轮全量通过"是在别的环境跑的。**这是本轮唯一未能验证的核心链路，装一个 Go 即可解除。**
- **换行符**：源码覆盖清单存的是工作树磁盘字节，而 `.gitattributes` 未给 `.xaml` / `.cs` 钉 `eol=lf`，本机 `core.autocrlf=true`。同一个 commit 换台机器克隆出来哈希即对不上。建议发布后专做一次归一化（需重算全部 158 条，勿在发版前动）。
- **本地临时编 Release 会改写 lock 文件**：传 `-p:VersionPrefix=<新版本>` 会把项目引用约束从 `[1.1.0, )` 改写成 `[<新版本>, )`，6 个 `packages.lock.json` 全部变脏。生产出包脚本走 git 快照不受影响，但**手工验证用的 Release 构建会污染工作树**，事后必须 `git checkout -- '*packages.lock.json'`。
- Release 构建硬依赖 gitignored 的 `.artifacts`（helper 包），新克隆无法构建。
- 生产出包依赖的 pwsh 位于 Codex 缓存目录，随时可能被清理。
- `Test-OtaUploadBundle.ps1` 的报告参数名是 `-OutputReportPath`，不是 `-ReportPath`。
