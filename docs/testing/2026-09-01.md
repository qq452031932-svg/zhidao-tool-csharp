## 下一步建议

当前 11 条真实主流程已经验收。下一步应按顺序进行：

1. 用户在已启动的 Release 界面检查这次批次结果、复制和导出交互是否符合使用习惯。
2. 再使用 50～100 条非关键测试链接做限流与长时间运行验收，重点观察会话过期、单条失败继续处理和结果导出。
3. 先完成一次应用内二维码重新登录实测，确认新 CK 自动落库和重新登录后的任务恢复。
4. 再逐步扩大到 1 万条导入的解析、分页和调度压力测试；不要直接用重要生产数据做第一次压力验证。
5. 上述主链路稳定后，等待用户说明广告插入、文件排除、数据统计和设置中心的具体规则，不提前扩展。

后续真实写操作仍必须由用户明确指定账号、测试链接和目标目录。若真实流程暴露问题，优先沿“导入 → 转存 → 自动分享 → 结果投影 → 导出”链路定位。
